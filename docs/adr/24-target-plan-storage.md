# #24 按目标端账户保存审阅计划

状态为已采纳。关联 [任务 #24](../tasks/24.md) 与[设计 §4.3](../design.md)。

## 背景

本机规划结果供之后的执行和恢复使用。管理机源文件及求值缓存可以独立变更，执行端仍需要审阅时的内容和期望资源集合。期望集合包含已收敛的资源，后续执行前可以重观测这些资源，发现新增漂移。

## 决定与影响

使用版本化 MessagePack 记录，包含核心 `Plan`、完整 `ResourceSet`、清单主机名和首次发布时间。计划 ID 将清单主机名纳入原计划的指纹，读取时核对仓库标识、目标身份、清单主机名与资源摘要。动作顺序和参数来自审阅时的核心计划。记录引用的目标内容按 SHA-256 单独存放，覆盖计划动作与期望资源。观测前置条件中的摘要用于比较目标状态。

默认状态根为 `/var/lib/dek`。管理员首次部署时可把私有状态根交给可信的目标端账户，规划进程和 Ruby 保持调用者权限。目标状态目录和文件分别使用 `0700` 与 `0600`，检查属主，沿目录描述符解析路径并拒绝符号链接。使用显式私有状态目录时采用相同约束。

选用目录内暂存、同步与禁止覆盖的原子发布，按先内容后计划的顺序提交。一个状态锁协调读取与发布，后续运行记录可在同一锁内固定计划引用。重复保存同一审阅结果会校验内容并复用原记录及发布时间。计划保留策略由 #26 确定。
