# #29 按名称管理 Linux 本地账户

状态为已采纳。关联[任务 #29](../tasks/29.md)和[设计 §6.2](../design.md)。

## 解析与复核

目标端同时读取本地账户数据库和 NSS 的名称、数字 ID 查询。外部条目、解析差异以及已占用的 ID 会在规划时报告。现有对象的显式 UID/GID 要求专门的迁移决策。声明有固定数字 ID 的对象先于同类自动分配的对象。主组及附加组通过资源依赖先行创建。执行前后均由目标端按名称解析，后续资源据此读取系统实际分配的 ID。

## 账户操作

`useradd` 和 `groupadd` 按目标默认设置创建账户，系统账户使用 `useradd --system`。没有声明的主组使用目标创建工具默认组。目录生命周期由目录资源负责。账户密码哈希和锁定状态由管理员管理，新账户沿用系统工具默认值。age 资源独立部署加密文件。

对已有账户，`usermod` 更新声明的说明、home 路径和 shell，附加组追加保留。单独的主组动作在 libc 账户锁和 Shadow 的 `passwd.lock` 内复核用户 UID、原 GID 和命名组，原子替换本地 passwd 的主 GID 字段。Linux 的 `usermod --gid` 会同时改写 home 树中的文件属组，这个动作只更新账户记录。执行记录保存实际观测的受管属性，账户凭据字段不进入计划和运行回执。
