# 使用持锁的原生事务补装仓库软件包

状态：随 [#46](https://github.com/xingjianxu/dek/issues/46) 实现。

计划保存请求包、全部依赖、候选版本及 SHA-256。`pacman --print` 无法提供同一份可直接提交的包事务。dek 复用目标的 libalpm，将本机包数据库锁、事务准备和提交绑定在同一个原生句柄上。准备时纳入已有软件包的待升级检查，并按审阅清单核对新增包和候选摘要。发现漂移后释放锁，保存新计划供审阅。

归档选择依次读取目标 pacman 的 `CacheDir`，把 SHA-256 匹配的归档与签名复制到单轮临时缓存。同名错误缓存保留原样。原生下载阶段按需补齐归档并执行目标签名策略。dek 核对归档摘要并固定文件后，再次取得数据库锁，重新准备和核对事务。通过后在同一锁内提交一次实际包变更。下载归档随本轮临时缓存回收。下载需要目标配置的自定义 `XferCommand` 时报告缺少该能力。

执行器只在原生事务就绪后创建新运行记录。安装成功后查询本地包数据库，等全部新增包通过版本核验，再处理依赖配置。中断续办可以用同一版本清单确认已安装的结果。完整仓库升级沿用仓库事务和执行准备接口，由 [#47](../tasks/47.md) 接入确认与升级后复核。
