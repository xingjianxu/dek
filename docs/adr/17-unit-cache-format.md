# 求值单元缓存的布局与发布

状态为已采纳。缓存用于复用管理机上的单元求值结果，并保留供诊断使用的来源。[Issue #17](https://github.com/xingjianxu/dek/issues/17) · [设计 §4](../design.md#4-按单元的文件缓存)

单个仓库共享索引需要协调无关单元的更新。以输入内容摘要命名每次结果会在编辑后累积历史文件，也需要额外索引定位原记录。采用稳定单元键定位独立文件，每次成功求值都可直接替换同一记录。Linux 使用绝对 `XDG_CACHE_HOME`，否则使用 `$HOME/.cache`。仓库 ID 采用工作副本规范绝对路径字节的 SHA-256。单元键包含阶段、规范单元标识、参数和可选目标标识，按对象键排序后的紧凑 JSON 计算 SHA-256。两种路径标识均用小写十六进制，单元键首两位用于分片。

缓存 v1 以 MessagePack 字段位置编码固定结构。最外层顺序为格式版本、单元键、求值器签名、记录。记录依次包含依赖列表、语义摘要和类型化输出。摘要保存为 32 字节，依赖变体保留字符串标签。自定义值中的对象保留原有键名。业务方构造语义投影并显式指定集合，数组默认保留顺序。来源变动可以更新记录，同时让忽略来源的下游语义摘要保持一致。

每次读取保存所见完整文件字节的摘要，或记录当时文件缺失。写入先生成并同步同目录的临时文件，再持本单元固定旁路锁复核旧记录及新结果依据的最新依赖。复核通过后原子重命名，并同步所在目录。读端直接读正式文件，写进程在重命名前被终止时仍可读取旧记录。锁文件在正常运行中保留，以便所有写进程对同一文件加锁。

格式版本、单元键或签名不符以及无法完整解码的文件按该单元未命中处理。改变字段位置或缓存表示时应升高格式版本，由下一次求值重建对应单元。删除缓存后，下次求值会按上述布局重建记录。
