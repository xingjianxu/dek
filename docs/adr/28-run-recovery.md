# 执行恢复与状态查询

状态为已采纳，关联 [#28](https://github.com/xingjianxu/dek/issues/28)。

执行 ID 绑定仓库、逻辑主机、目标身份和请求标识。重发请求先读取已有执行，确认该请求仍绑定原计划。完成记录可以在计划内容回收后读取。未完成记录继续固定其计划和内容，使用原执行的上下文续办。普通 `apply` 提示续办最近一次未完成执行，`apply --run` 允许选择更早的记录。默认 `apply --plan` 发起独立请求，显式 `--request-id` 用于重发。

执行锁覆盖恢复判断、观测和派发。已核验的动作保持原回执。恢复时若发现这些资源有新差异，应重新审阅。曾调用过的动作先由后端复查。已达到目标状态的动作可核验完成，明确还需执行且前置条件匹配的动作才开启下一次尝试。对包事务、重载或重启，普通当前状态不足以确认先前效果，保留待核验与诊断，直到后端能提供可确定的结果。

待续办服务通知随原执行保留。`plan` 及 `status` 展示通知，其执行 ID 用于恢复原审阅顺序。预览信息独立于新计划的动作和摘要，避免通过一次新规划重复尝试仍待核验的效果。
