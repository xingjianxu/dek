# 受管 AUR 构建、审阅与续办

状态为已采纳，关联 [#49](https://github.com/xingjianxu/dek/issues/49)。

目标端沿用 [#48 的构建账户与候选查询](48-aur-build-preview.md)。普通补装只构建缺装的受管包。完整升级在记录仓库事务结果后继续复核受管 AUR 候选，再按包执行。目标锁覆盖仓库阶段与后续的计划复核。AUR 候选或依赖漂移时，新计划仍保留后续候选复核，原运行保留已核验的仓库事务。

目标端为每项构建生成带精确候选版本的 `paru -S --aur --review` 命令。本机有终端时直接交互，SSH 的 `apply --interactive` 通过 [独立终端](43-ssh-execution-and-terminal.md) 在目标运行该命令。查询与构建使用同一账户、主目录和命令环境。paru 处理 PKGBUILD、依赖、缓存、源码签名及安装授权。

`plan --rebuild-aur` 计划重建已安装的受管 AUR 包，也可与 `--upgrade` 组合。重建动作记录 pacman 本地包数据库中已安装记录的设备、inode 和纳秒级变更时间。核验同时比较版本和记录代际，能识别同版本重装以及已完成但回执丢失的重建。续办时先查实际安装状态，已满足的动作直接核验，仍满足原前置条件的动作可再次运行。构建记录只进入计划和执行诊断。
