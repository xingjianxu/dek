# 按声明图和模块输入复用合并与展开

状态为已采纳。[Issue #19](https://github.com/xingjianxu/dek/issues/19) · [设计 §4](../design.md#4-按单元的文件缓存)

合并单元按清单主机及目标绑定保存，依赖包含本轮正向遍历中涉及的单元键、语义摘要及顺序。以完整文件内容为依赖会使位置修改触发重新合并。缓存记录用赋值序号表示来源，读取时用本轮声明的位置恢复诊断。schema 签名涵盖类型、合并规则和默认值。读取及发布前核对声明图的采集记录版本、本地文件、目录清单和环境变量。原生 I/O 随每次运行重新采集，合并使用本轮采集结果。

展开单元按主机、目标绑定及模块独立保存。依赖涵盖模块声明的读取范围，省略范围时采用完整可见选项。内置模块的摘要使用生效定义及其文件位置。其展开记录使用来源引用，行号和 JSON Pointer 从本轮生效配置恢复。仓库 Ruby 模块可以直接读取传入的位置信息，因此展开依赖涵盖它实际收到的选项和来源。只有采用 SDK 输入约定的仓库模块可跨运行复用，复核时沿用采集阶段的文件、目录、环境及提供者查询规则。提供者复核后再核对声明图和合并记录，以处理查询期间输入发生的变更。

缓存保存类型化的资源草稿，发布前校验内联内容对象的摘要。Caddyfile、SSH 公钥文件和 age 密文继续在每次资源组装时按当前字节计算摘要。目标端规划继续对本轮资源清单执行能力检查与实时观测。
