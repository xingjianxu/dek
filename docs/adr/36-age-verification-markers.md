# #36 在目标端验证 age 文件

状态为已采纳。关联[任务 #36](../tasks/36.md)和[设计 §6.3](../design.md)。

## 背景

规划需要区分目标内容一致、本地漂移、只能在应用时核对和权限漂移。管理端和审阅记录只需要密文摘要、部署设置及目标端核验结果。

## 决定与影响

Linux 目标端使用独立的 32 字节随机密钥生成 HMAC-SHA256 标记。标记绑定规范化落点、密文 SHA-256、声明顺序中的 identity 路径和受管文件字节。标记和密钥使用现有目标状态目录的私有权限检查。状态根下的 `secrets/` 为 0700，`verification.key` 和按落点寻址的 `<id>.marker` 为 0600。标记包含格式版本、密钥标识、绑定摘要和认证码。[#37](../tasks/37.md) 负责生成密钥、部署成功后的原子发布和实际内容变化的通知。

规划缺少可用标记时提示应用时核对。密文或 identity 设置改变时也要在应用时核对。权限、属主和属组独立比对，默认权限为 0600。计划前置条件只保存核验结论和 POSIX 属性。文本和 JSON 复用同一核验结论及密文元数据。

落点和可检查的 identity 逐级沿目录描述符检查，拒绝符号链接。规划检查同一资源清单中的 identity 路径与受管路径冲突，包括可观察的硬链接。目标账户或父目录可通过先行资源创建。需要提权才能检查的 identity 在实际部署前再次检查。
