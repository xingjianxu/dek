# 本机规划入口与计划输出

状态为已采纳。关联 [#16](https://github.com/xingjianxu/dek/issues/16) 和[计划格式决定](3-versioned-plan-format.md)。

CLI 与 show 共用仓库、主机选择和求值。规划使用同一个 Ruby 会话处理主机、profile 和启用的仓库模块，并在资源组装时读取部署文件。这样文本或 JSON 输出的内容来自同一份目标端 Plan。若管理端自行生成动作或计划 ID，则输出无法与目标端校验过的内容绑定。

本机目标注册真实的文件观测能力，可对缺失文件、已存在的内容和 Unix 权限生成差异。账户、软件包、服务等能力由相应目标后端提供。验收使用内存后端注入 Caddy 所需的全部能力。生产入口在缺少声明所需能力时报告目标和来源。

输出中的 `plan_id` 取自目标生成的 ID，并在文本中显示同一值。JSON 保留版本、绑定、内容摘要、动作、来源和前置条件，同时增加仓库清单中的主机名 `host`。核心 Plan 的持久化格式沿用独立的版本约定。
