# SSH 目标的绑定与握手

状态为已采纳，关联 [#40](https://github.com/xingjianxu/dek/issues/40)。

清单中的 SSH 别名由 OpenSSH 解析，连接地址、身份、代理和可信主机密钥由本机 SSH 配置管理。别名可以被重新指向另一台同样受 OpenSSH 信任的主机。需要用清单独立记录预期的 dek 标识，才能在这种情况下拦住目标请求。

保留 `"target": {"ssh": "lab-server"}`。默认用清单的逻辑主机名核对目标返回的 `TargetIdentity.id`。当前本机注册器以目标系统主机名报告该标识。逻辑名与实际主机名不同时，在同一 host 项填 `"targetId": "actual-hostname"`。比较使用原样字符串。纳管目标应配置唯一主机名，主机改名时同步核对清单绑定。由首次连接或当前别名的解析结果自动记录预期标识会接受配置错误时的第一台主机，因此预期值来自配置。主机密钥仍负责认证 SSH 对端。

文件路径及资源字段通过 JSON 帧传输。OpenSSH 使用独立会话、严格主机密钥检查和固定的 `dek __target-stdio` 命令。标准输入与输出承载协议，标准错误保留 SSH 和目标诊断。管理端发送支持的版本，再校验目标回复的版本和标识。目标端从本机注册器报告系统和资源能力。版本协商失败时只报告支持的版本。只有校验成功的会话才提供发送请求的接口。

协议独立于 Ruby 求值器和计划文件格式。首版用换行分隔的 JSON，每帧至多 8 MiB。单会话依序验证请求与回复的请求 ID。首个只读请求把原始路径交给目标注册器并返回原始值和规范化结果。资源计划和内容传输由后续任务增加。
