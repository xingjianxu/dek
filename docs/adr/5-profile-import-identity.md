# #5 按别名和参数识别声明图中的 profile 单元

状态为已采纳。

## 背景

几个 profile 可能引用同一项公共配置。声明图需要复用本次采集结果，同时保留各条引用自己的来源位置和传入参数。参见 [#5](../tasks/5.md)。

## 考虑的方案

- 把每次引用展开为独立节点。引用直接拥有子节点，重复引用会重复采集并累加同一组赋值。
- 按入口文件和参数归并。多个别名共用同一入口时可以复用采集，但这些注册可能带有各自的输入策略。
- 按清单别名和规范化参数归并。图复用同一注册的等值调用，并保留各条引用作为独立的边。

## 决定与影响

采用别名和规范化 JSON 参数作为同一主机图中的 profile 身份。参数的对象键递归排序，数组保留元素顺序。图按深度优先的后序遍历输出，被引用单元排在引用者之前，每条引用仍保留原始位置。跨运行的缓存策略在后续任务交付。参见 [#18](../tasks/18.md)。
