# #47 执行已审阅的 Arch 滚动升级

状态为已采纳。关联 [任务 #47](../tasks/47.md)、[升级预览](45-isolated-arch-upgrade-preview.md)和[设计 §7.2](../design.md#72-常用命令)。

## 决定

录入审阅计划后，在目标执行锁内以其原范围重新观测。完整升级重新预览所有仓库包。计划过期时，保留记录写入时区分普通规划和完整升级，管理端据此生成待审阅的新 ID。

升级执行建立只用于持有本机 pacman 锁的 ALPM 句柄。按目标 pacman 配置在同一文件系统上刷新私有同步目录，复制本地包记录和公共密钥环用于复核。按候选版本、摘要及完整事务范围校验后，复用独立补装的归档暂存、签名验证和原生事务守卫。

执行器持久化动作尝试后，原子发布一份与复核快照等价的同步数据库。提交句柄使用真实数据库路径获取原生锁，再次校验事务范围和暂存归档，保证安装脚本和包记录按系统路径发布。整个流程持有 dek 执行锁，原生锁交接期间若其他 pacman 操作改变事务，提交前复核会停止。首次复核范围不符时保持本机同步数据和已安装包。发布后发生包事务错误或中断时，可能留下比本机包更新的同步元数据，行为与常规 `pacman -Syu` 刷新后失败一致。普通补装在该状态会重新判定与本机的兼容性。结果不明的有变更事务依据本地数据库确认审阅后的版本和包记录，无法确认时保留诊断供人工查核。

## 升级后续

从真实本地包数据库核验并保存事务回执后，使用相同的资源声明、输入及内容重新观测后续配置。超出审阅范围时保存新的配置计划，并在原执行中记录该 ID。已经核验的仓库事务可由 `status` 查看。重放原请求时返回同一执行与后续审阅。先前已经入队的通知仍保留续办路径。

仓库事务沿用包后端的执行校验。受管 AUR 动作需要其执行后端可用，规划预检见 [#48](../tasks/48.md)。
