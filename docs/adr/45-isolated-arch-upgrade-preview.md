# 在独立数据库中准备 Arch 软件包事务

状态：随 [#45](https://github.com/xingjianxu/dek/issues/45) 实现。

`pacman --print` 会关闭包冲突检查，添加列表也无法完整表达冲突移除。自行解析元数据并求解依赖需要维护一套与 pacman 同步的解析规则。dek 使用 Arch 的 libalpm 16 准备原生事务，读取添加和删除清单，并记录原生替换决策。预览选择第一个依赖提供者，将解决冲突所需的移除提交审阅。忽略包设置保持有效，依赖缺失时整份规划报错。

`pacman-conf` 展开目标的配置、仓库顺序和镜像。规划复制本机包数据库与需要的公钥信任文件，并把同步数据库和下载放到单独的临时目录。启用 `Sync` 的仓库在完整升级预览时下载新副本，禁用 `Sync` 的安装或升级仓库使用目标已有的有效快照。仓库配置使用 `XferCommand` 且需要刷新时，预览会报告需要该下载能力。libalpm 在 Arch 目标上运行时加载，通用 workspace 构建和所有受管包已满足的本地查询路径无需链接它。

普通规划发现仓库缺包时，先检查已有同步数据。软件源候选缺失、已有待升级包、已装版本比同步数据更新或补装会改变现有包时，转入完整升级预览。普通 `apply` 遇到升级计划，在创建执行记录之前先返回已保存的计划 ID。

计划用单个 `RepositoryTransaction` 表达一次原生事务。记录直接请求的包名、仓库候选及其 SHA-256、所有增删替换和升级、涉及包的已安装版本前置条件。目标规划器将配置动作排在仓库事务之后。SSH 请求在显式升级时携带升级模式，普通规划沿用原有请求形式。受管 AUR 目标保留来源和已装状态，候选版本及构建预检由 [#48](../tasks/48.md) 补齐。执行器在同一持久化动作上由 [#46](../tasks/46.md) 和 [#47](../tasks/47.md) 接入经核验的补装和升级。
