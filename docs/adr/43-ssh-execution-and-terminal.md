# SSH 执行、重发与独立终端

状态为已采纳，关联 [#43](https://github.com/xingjianxu/dek/issues/43)。

管理端沿用已核对主机身份的 OpenSSH 会话。执行请求绑定仓库、清单主机、目标计划及请求标识。目标执行器在记录 `run_id` 后发出与协议请求 ID 相关联的事件，执行完成或停止后返回结构化结果。管理端在使用自动生成的请求标识时先输出计划 ID 和请求标识，收到开始事件后立即输出 `run_id`。断线后先建立新的已绑定会话查询记录，用户可按同一次请求重发或按原运行续办。

等待全部动作完成再发送执行 ID，会使丢失最后回复时难以找到原运行。启动事件让正在执行或已中断的运行可定位，首次事件之前的连接中断则可借助稳定请求标识恢复。重复请求和明确的恢复都交给共用执行器。已持久化的结果与目标执行锁仍用于恢复、并发和动作前置条件的判断。

普通协议会话使用 OpenSSH 的 `-T`。用户使用 `apply --interactive` 时，后端可在已审阅动作中请求独立终端。目标为这次动作在私有状态目录创建仅允许执行账户访问的短期 Unix 套接字，并在协议事件中发送一次性标识。管理机通过独立的 `-tt` 会话调用隐藏端点。该端点只接受 32 位小写十六进制附件标识，向同一账户拥有的待办套接字接收目标端已构造的程序及参数，在会话的终端内运行。终端文本在管理机的控制终端显示，主协议只承载事件和类型化执行结果。没有可用的附件时该入口只返回诊断。

文件和其他进程内操作使用目标登录账户按部署配置取得的权限。辅助命令需要 sudo 或其他交互授权时，在对应动作中请求终端。没有选择交互时，声明需要终端的动作保持待执行，之后可用 `apply --run <ID> --interactive` 续办。Ruby 始终由管理机启动。
