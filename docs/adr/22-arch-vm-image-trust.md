# #22 以固定发布公钥验证 Arch 测试基盘

状态为已采纳。

## 背景

活动测试轮次共享基础镜像，同一个版本号需要始终指向相同的已验证字节。Arch 镜像目录同时提供滚动别名和版本路径，arch-boxes 项目另行发布用于验证镜像的 CI 公钥。参见 [任务 #22](../tasks/22.md)、[官方镜像索引](https://geo.mirror.pkgbuild.com/images/) 和 [arch-boxes 发布说明](https://github.com/archlinux/arch-boxes/blob/7f733af26fe9a0c93fdabba13e7803cbe803374a/README.md#releases)。

## 决定与影响

按 Arch 镜像目录中的版本名选择镜像。镜像和 SHA-256 文件分别经过分离签名验证，摘要行须包含所选版本的原始文件名。脚本使用随仓库提交的官方公钥，在独立的 GnuPG 目录验证主指纹 `1B9A16984A4E8CB448712D2AE0B78BF4326C6F8F`。公钥轮换纳入代码评审和验证。

下载文件在开发数据目录的缓存中暂存。每个版本持有独立写锁，通过验证后在基盘父目录内原子发布只读目录。显式重复提供已存在的版本时核对已发布摘要，保留既有目录和活动差分盘的引用。基盘中保存签名、摘要及 JSON 验证记录，启动端可离线重验。
