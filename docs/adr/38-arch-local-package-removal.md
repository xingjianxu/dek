# #38 使用本地包数据库和原生事务锁审核卸载

状态为已采纳。关联 [任务 #38](../tasks/38.md) 与[设计 §6](../design.md)。

## 背景

已有包的普通规划和应用需要能离线工作。明确卸载需要记录审阅时的安装版本，且在开始原生事务后仍能发现其他 pacman 进程造成的版本变化。

## 决定与影响

使用 pacman 的本地查询判断包名及安装版本。软件包来源属于声明标识。安装记录本身无法证明包来自哪个仓库，当前后端支持官方仓库资源，遇到 AUR 资源会指出该来源需要对应后端。缺包在本地状态中为未安装，仓库候选的事务规划由 #45 接入。

明确移除使用 pacman 的只读预览并要求范围严格等于声明的单个包。实际执行前复核审阅版本，再开始 native pacman 卸载事务。为该事务在目标端私有临时目录生成一个 `PreTransaction` hook，核对本次事务的包集合，并在 pacman 的数据库锁下重新读取安装版本。锁内不匹配即终止。移除保留 pacman 本身的依赖校验，完成后从本地数据库复核。 [pacman 手册](https://man.archlinux.org/man/pacman.8.en) · [ALPM hooks](https://man.archlinux.org/man/alpm-hooks.5.en)

集成夹具使用 Arch 签名的本地包归档和严格的本地签名策略。来宾测试通过独立的 native pacman 事务模拟版本变化，并以探针统计应用入口的 pacman 操作。
