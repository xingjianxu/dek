# 声明采集缓存的作用域和输入复核

状态为已采纳。[Issue #18](https://github.com/xingjianxu/dek/issues/18) · [设计 §4](../design.md#4-按单元的文件缓存)

始终按主机建键会重复采集共享 profile。只用共享键则无法区分读取相同路径的不同目标。基础单元键使用优先级层、入口名称、规范仓库相对入口路径及参数。只有求值时读取目标事实、能力或文件的记录才加上清单主机和目标绑定。读端先检查当次目标的记录，再检查共享记录。求值前捕捉两个可能的记录版本，成功后按实际输入范围发布。

静态 JSON 使用带版本的解析器签名。Ruby 只跨运行复用显式采用 SDK 输入约定的单元。Ruby 签名基于协议版本、嵌入的 SDK、按执行路径定位的解释器文件、文件内容及修改时间，以及影响 Ruby 加载的环境变量。Rust 在不启动 Ruby 的情况下计算签名。签名不可取得时仍可按普通方式求值。

复核先读取本地文件、目录和环境变量，再通过采集时的提供者核对目标及 HTTP 输入。先核对本地输入可使删除了远端读取的配置直接求值。发布时再次核对签名和完整输入列表。同一输入在一次复核中使用同一当前观测，求值时读取到相互矛盾的状态会使发布失败。失去写入竞争时重新查询一次。加载 Ruby 源码时记录排在已选路径之前的缺失 `.rb` 候选，以识别新文件改变加载结果的情况。

采集语义摘要保留导入的名称和参数、赋值顺序及原始选项值。赋值所属文件影响相对路径语义，因此纳入摘要。文件内的行号和 JSON Pointer 继续保留在缓存记录中，位置变化可以更新诊断而保持语义摘要。待部署文件继续由资源组装阶段读取。
