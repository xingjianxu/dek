# 目标端规划的能力记录与顺序

状态为已采纳。关联 [#14](https://github.com/xingjianxu/dek/issues/14) 和[设计 §1.1、§4.3](../design.md)。

规划器在读取资源状态前校验完整清单、目标路径同一性和依赖关系。集中校验能统一发现跨后端的路径别名。交由每个资源后端独立完成该步骤，需要在后端之间重建共享的路径索引。登记在同一目标上的后端使用同一个路径同一性函数，原始目标路径继续传给后端和计划。

规划记录参与校验的资源能力、版本及已用属性。后端默认只兼容同一版本，可显式声明兼容的旧版本。复核比较目标标识及计划记录的能力子集。记录目标当前全部能力会因新增无关能力而使旧计划失效。传入的求值输入观测另外随计划保存。

规划按资源依赖排序，使用规范身份为无依赖的资源确定顺序。后端逐个返回某个资源的动作和前置条件。即使中间资源无需动作，下游动作也保留对上游动作的依赖。服务通知在触发动作之后按 unit 汇总，重启覆盖重载。该计划已安排在所有触发动作之后启动同一服务时，把触发依赖接到启动动作。服务在触发动作前启动时，通知后端按计划的运行状态准备通知。计划停止服务时跳过该 unit 的通知。

文件资源的 `owner`、`group`、`mode` 等能力属性沿用声明字段名。systemd 能力用 `user` 和 `userGlobal` 标记相应作用域，以 `reload` 和 `restart` 标记通知效果。包后端用 `aur` 标记 AUR 支持。新增属性名称属于对应的资源能力版本。

目标端对完整清单的紧凑 JSON 计算 SHA-256 摘要，再对 ID 留空的计划计算 SHA-256 并以小写十六进制作为计划 ID。相同目标、仓库、清单、观测和动作结果产生相同 ID。计划的持久化、有效期与执行记录由后续组件处理。
