# #26 在目标状态事务内回收过期审阅

状态为已采纳。关联 [任务 #26](../tasks/26.md) 与[维护者的保留策略决定](https://github.com/xingjianxu/dek/issues/26#issuecomment-7082964755)。

## 背景

管理机可以删除自己的求值缓存，目标端仍需要在有效期内读取计划的原始内容。进行中或待恢复的执行可能超过计划的有效期。回收必须与新执行固定引用协调。

## 决定与影响

计划默认保留七天，目标端通过受保护的 `retention.json` 配置 `planTtlSeconds`。保存新计划时，在状态锁内读取计划和运行记录，保护有效计划、未完成执行与新计划的内容引用。先持久化过期标记，再移除过期计划，最后移除无引用内容。运行记录继续用于状态查询。

首次保存沿用规划指纹作为 ID。有效期内相同审阅复用原记录。相同计划过期后续发独立 ID，规划指纹继续用于比对内容。过期标记只保存 ID、绑定和过期时间。标记落盘后，即使计划文件因中断或待恢复引用仍存在，原 ID 也不再用于新执行或被再次签发。存储继续读取此前没有续发序号的计划记录。

对新执行检查有效期。已有未完成执行通过绑定的运行记录读取原计划和内容，适用相同的归属及完整性检查。回收和建立运行引用共用目标状态锁。
