# #31 在目标文件系统校验并原子发布普通文件

状态为已采纳。关联 [任务 #31](../tasks/31.md) 与[设计 §6](../design.md)。

## 背景

审阅计划需要区分内容漂移、属性漂移与显式删除。多个受管文件的校验可能依赖整组审阅内容。目标端需要避免覆盖审阅后发生变化的文件，并限制临时文件和路径解析的范围。

## 决定与影响

Linux 文件后端按目录描述符解析普通文件，拒绝符号链接。内容和已声明属性分别影响差异。属主及属组通过目标名称服务解析。写入时在目标父目录创建私有暂存目录，应用计划字节和属性并校验读回值。在提交边界复核目标仍是刚观测的版本，再用同文件系统的原子重命名发布。原本省略的属性沿用既有文件，收敛后的普通应用跳过写入。

文件组校验器由目标后端注册，接收包括未变成员在内的整组已审阅内容。输入在只读封存的文件描述符中暂存。执行器在派发第一个动作前完成整组校验，因此含失败输入的组不会替换任何目标文件。实际发布仍按各目标文件的依赖顺序进行。整组校验通过后的各项写入分别核验并记录结果。

显式 absent 可移除现存普通文件。撤销声明结束管理，既有文件由其当前状态继续使用。
