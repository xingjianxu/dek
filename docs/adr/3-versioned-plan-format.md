# 计划格式版本与动作标签

状态为已采纳。适用范围是目标端持久化的审阅计划及同一计划的 JSON 展示。[Issue #3](https://github.com/xingjianxu/dek/issues/3) · [设计 §4.3](../design.md#43-执行计划有效期与执行记录)

计划要同时保留可审阅的动作名称和紧凑的存储结构。整份计划用字段名编码会重复写入固定键名。用枚举位置编码动作会使定义顺序成为动作身份，调整顺序时旧记录可能被解释为另一种动作。

计划首字段 `formatVersion` 记录独立的存储版本，首版值为 `1`。MessagePack 按字段位置编码固定结构，动作保留其稳定的字符串标签。JSON 保留字段名和相同的动作标签。两种表示均以有序数组保存动作，并记录动作 ID、依赖、来源和前置条件。内容对象通过摘要引用。

调整字段位置或改变动作的含义需要新格式版本。读端拒绝不支持的格式版本及无法识别的动作，以便调用方定位错误并请求重新规划。握手的协议版本及资源能力版本各自演进。JSON 示例和往返测试记录了 v1 的表示。[计划夹具](../../crates/dek-core/tests/fixtures/plan-v1.json)
