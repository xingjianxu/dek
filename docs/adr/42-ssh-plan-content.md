# #42 在 SSH 会话中协商规划内容

状态为已采纳。关联 [任务 #42](../tasks/42.md)、[设计 §5](../design.md)和[SSH 握手](40-ssh-target-handshake.md)。

## 背景

管理端拥有资源声明与内容，目标端拥有实际状态和已校验的对象。文件、systemd 定义、公钥源文件和 age 密文都可用同一个 SHA-256 对象接口。本机规划和 SSH 规划需要生成相同格式的审阅记录。

## 决定

目标协议 v1 增加 `preparePlan`、`uploadContent` 和 `finishPlan`。声明包含仓库标识、清单主机名、资源集合及求值时使用的目标观察。内容清单从资源中的摘要引用派生并去重。目标以 `missingContents` 列出缺少的摘要。管理端确认每个摘要都来自本次声明，再发送对象。

内容以最多 256 KiB 原始字节的 Base64 分片逐个传输，沿用 SSH 标准输入输出上的 JSON 帧。这个方式让二进制内容可复用现有帧解析器，也允许对象大于单帧上限。目标在最后一个分片收到后复核完整摘要，原子保存对象后才确认该分片。断线丢弃尚未完成的分片，已经保存的对象可在下一次协商中复用。age 资源传输及保存的对象是原始密文。

协议请求之间释放状态锁。目标端在完成规划的请求中持锁复核全部对象、读取主机实际状态并保存计划。其他会话回收尚未引用的内容时，目标可在完成请求中再列出缺失摘要。协议错误或校验失败终止本次规划，已经校验的对象仍遵循目标状态保留策略。

## 影响

用同一规划器和状态记录实现本机与远程计划。配置仓库、求值器和缓存由管理端提供。执行使用计划中固化的内容摘要与目标端保存的对象。远端 OpenSSH 命令仍由已配置的固定入口启动。管理端和目标端都需安装支持远程规划请求的版本。

声明和计划回复沿用 8 MiB JSON 单帧上限。上传累计一个完整对象的内存，规划时按现有后端接口在内存中持有全部引用字节。

整包传输会让已缓存内容重复上行。等待整套文件收齐后统一写入会丢失已经传完的文件。持续持有状态锁会让断线或停顿的客户端阻塞其他会话。
