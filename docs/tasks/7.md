# #7 将模块输出合成为带文件摘要和依赖的资源清单

[GitHub Issue #7](https://github.com/xingjianxu/dek/issues/7) · Feature

- 分支：`issue-7-resource-expansion`
- Worktree：`/data/dek-dev/worktrees/7-resource-expansion/`

## 交付目标

提供内置与用户模块共用的展开入口，从生效选项得到无冲突、可交给目标端的 `ResourceSet`。

## 范围与接口

在 `crates/dek-controller` 的 `modules` 建立展开注册表与资源汇总。管理端负责源文件定位与内容摘要，目标平台负责目标路径同一性。这里只产出清单和输入记录，内容对象持久化及传输由对应组件接管。

设计位置：[docs/design.md](../design.md) §1.1、§2.1、§2.2、§3、§4.2、§6。

直接前置：[#6](6.md)、[#3](3.md)。

## 实施步骤

1. 按模块启用条件调用展开器。依据 `readsOptions` 记录使用的选项，未声明精确依赖时记录全部可见选项。注册模块本身不会产生受管资源。
2. 按包来源与名称、账户或组名、unit 作用域与名称等标识合并重复声明。对路径保留原始格式并先处理同拼写冲突，别名同一性由目标后端判断。保留贡献模块和来源，检查依赖及循环。
3. 区分声明文件相对的 `source_file` 与原样传输的目标路径，在规划阶段由 Rust 读取待部署文件并生成内容摘要。保留依赖边和服务通知触发条件。

## 验收条件

- [x] 让两个模块给同一目标文件声明不同内容，合成失败且输出两个模块及配置位置。系统和 Alice 的同名 `backup.timer` 可并存。
- [x] 在测试的两个不同目录各放一份同名 `Caddyfile`，以各自声明文件为基准正确读取内容。只改源文件后内容摘要变化，原 `UnitSpec` 可再次使用。
- [x] 让两个样本资源互相依赖，产生可定位的循环诊断。移除整个模块声明时资源从集合消失，未合成 `absent` 或停止服务动作。
- [x] 对精确声明 `readsOptions` 的模块及省略该字段的模块展开，前者只记录指定生效选项，后者记录完整可见输入。

wks-lab 的展开测试验证选项范围、来源相对文件及摘要更新、同名不同作用域、相同资源合并、通知与依赖循环。
