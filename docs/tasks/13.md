# #13 让仓库注册的 Ruby 模块按合并后的 option 展开资源

[GitHub Issue #13](https://github.com/xingjianxu/dek/issues/13) · Feature

- 分支：`issue-13-custom-module-expansion`
- Worktree：`/data/dek-dev/worktrees/13-custom-module-expansion/`

## 交付目标

让配置仓库以静态 schema 和 Ruby 展开器扩展内置模块集，并复用相同的资源校验与来源诊断。

## 范围与接口

在 `crates/dek-controller` 的 `repo`/`modules`/`eval` 接入用户模块注册、schema 加载和 Ruby `expand` 调用，在 `sdk/ruby` 提供展开器返回资源的入口。模块只提交声明。具体资源操作由已注册的目标后端负责。

设计位置：[docs/design.md](../design.md) §2、§2.2、§3、§3.1、§4.2。

直接前置：[#4](4.md)、[#7](7.md)、[#11](11.md)、[#12](12.md)。

## 实施步骤

1. 读取 `dek.json` 的 `schema`、`expand`、可选 `readsOptions` 与 `inputs`，按内置注册规则合并 schema，重复定义指出双方来源。
2. 使用同一 Ruby 会话把已生效 option 交给展开器，按 `readsOptions` 划定输入。未给清单时以全部可见选项作为依赖。
3. 校验返回资源及其依赖、文件引用并送入统一汇总，保留模块来源，并复用 [#12](12.md) 的 SDK 输入通道记录加载代码与实际读取的外部输入。

## 验收条件

- [x] 建立 `modules/lab-backup/{options.json,expand.rb}` 后分别关闭、启用该模块。关闭时无备份资源，启用后得到 timer、service 及配置文件，且值取自 host 对 profile 的覆盖。
- [x] 令用户模块与内置模块重复定义 `services.caddy.enable`，加载报出两个定义。令展开器返回非法字段，错误指向展开阶段与模块源文件。
- [x] 分别指定 `readsOptions: ["lab.backup"]` 及省略该字段，观察展开输入记录分别为该路径和完整可见配置。仅启用静态内置模块的仓库不启动 Ruby。

wks-lab 使用 Ruby 3.4.12 验证模块启用、合并后选项、加载代码和文件输入、获胜声明相对路径、重复内置 schema 和非法资源输出。
