# #42 按摘要补传缺失内容并让远端生成计划

[GitHub Issue #42](https://github.com/xingjianxu/dek/issues/42) · Feature

- 分支：`issue-42-ssh-plan-content`
- Worktree：`/data/dek-dev/worktrees/42-ssh-plan-content/`

## 交付目标

使远程 `dek plan -H <host>` 只传资源声明与目标缺少的引用内容，由目标端观测并返回持久化计划。

## 范围与接口

在 `dek-controller::transport`、`dek-target::state` 和 `dek-cli` 装配远程规划。复用与本机相同的 planner 和计划格式。

设计位置：[docs/design.md](../design.md) §3、§4.3、§5、§7.2、§9。

直接前置：[#40](40.md)、[#24](24.md)。

## 实施步骤

1. 管理机完成求值，从 `ResourceSet` 汇出资源声明及内容摘要清单。目标端按其现有对象回复缺少的摘要。
2. 只传被请求的静态内容，校验后提交至内容存储。中途断线后可利用已完整写入的对象再次协商。加密文件按密文处理。
3. 目标端完整校验所需对象并观测实际主机，生成并保存绑定该目标、资源摘要与内容的计划，向管理机返回可审阅的动作和 ID。

## 使用与验证

通过清单的 `target.ssh` 和可选 `targetId` 绑定 SSH 目标。管理员首次部署时在目标机运行 `sudo install -d -m 0700 -o <SSH账户> /var/lib/dek`，并确认 SSH 会话的 PATH 可找到支持远程规划的 dek。管理机执行 `dek plan -H <host> --json`，按返回的 `plan_id` 在目标状态目录定位已审阅计划。协议与内容提交方式见 [ADR](../adr/42-ssh-plan-content.md)。

运行 `./scripts/check` 验证本机与进程测试。按 [#40](40.md) 构建管理机和 Arch ABI 两份二进制，运行：

```bash
scripts/tests/ssh-plan-content v20261115.625457 \
  "$CARGO_TARGET_DIR/debug/dek" "$CARGO_TARGET_DIR/x86_64-unknown-linux-gnu/debug/dek"
```

脚本在专用来宾上记录真实 SSH 传输、目标计划及对象摘要。

## 验收条件

- [x] 两份资源引用同内容并另引用一个已有对象，首次只传一份缺失对象的字节。重复规划的内容有效载荷为零，计划仍基于当次目标观测。
- [x] 在多文件传输中断开并重连，只补已缺对象。传入不符摘要的字节时请求失败，目标不会发布引用损坏对象的计划。
- [x] 保持仓库和求值缓存不变，手工改变目标受管文件后再次远程规划，返回对应文件动作与可读取的 plan_id，规划期间该文件保持手工值。
