# #19 沿 profile 引用和生效选项增量合并与展开资源

[GitHub Issue #19](https://github.com/xingjianxu/dek/issues/19) · Feature

- 分支：`issue-19-cache-expand-graph`
- Worktree：`/data/dek-dev/worktrees/19-cache-expand-graph/`

## 交付目标

只重算依赖发生语义变化的合并或展开单元，并让来源更新和动态引用在本次运行生效。

## 范围与接口

在 `dek-controller::modules`、`eval` 与 `cache` 将 `HostConfig` 合并及各模块的 `ResourceSet` 展开接入独立的缓存节点，复用既有资源展开与静态文件寻址实现。

设计位置：[docs/design.md](../design.md) §3、§4.1、§4.2、§8。

直接前置：[#18](18.md)、[#6](6.md)、[#7](7.md)。

## 实施步骤

1. 沿当前 host 的正向引用访问需要的 profile，并为合并节点记录各输入单元的键与语义输出摘要。成功求值后用新依赖完整替换旧依赖。
2. 按模块声明读取的生效 option 计算展开键的依赖摘要。未提供精确依赖声明时取全部可见选项。保留输出不变时的下游命中，并更新发生位移的来源。
3. 在组装最终清单时重新核对 `source_file` 内容，给目标端提供本轮的内容摘要。交给目标 planner 实时读取受管资源状态。

## 实现与验证

`SchemaRegistry::merge_cached` 使用选定声明图的有序依赖。`ModuleRegistry::expand_cached` 独立缓存各模块的展开结果。静态内容在最终组装时读取，来源位置从本轮已采集声明取得。[增量缓存设计](../adr/19-incremental-expansion.md)

集成测试覆盖动态引用切换、精确与全量选项依赖、位置变化、静态内容变化、被覆盖值变化，以及旧声明图、阶段间的本地变更和无效内联内容摘要。[增量展开测试](../../crates/dek-controller/tests/incremental_expansion.rs)

## 验收条件

- [x] 在动态入口中把导入从 profile A 换成 B，立即看到 B 生效。下一轮编辑 A 不再使该 host 的合并失效。
- [x] 改共享 `base` 的 Git 选项，Git 结果更新而 Caddy 模块继续命中。对未声明精确依赖的自定义模块，同一变化会引起重新展开。
- [x] 仅在上游配置前插入空行，诊断来源更新且下游语义摘要不变。只改静态 `source_file` 内容，最终清单换用新摘要，未主动读取该文件的 Ruby 单元继续命中。
