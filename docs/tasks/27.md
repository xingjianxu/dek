# #27 在本机按依赖顺序执行并核验已审阅的计划

[GitHub Issue #27](https://github.com/xingjianxu/dek/issues/27) · Feature

- 分支：`issue-27-local-apply`
- Worktree：`/data/dek-dev/worktrees/27-local-apply/`

## 交付目标

让本机的 dek apply 与 dek apply --plan <ID> 通过目标端执行类型化动作，并给出实际执行的 run_id。

## 范围与接口

在 dek-target::executor 实现加锁、复核、调度和核验，在 dek-cli 接入本机 apply；复用目标计划、内容对象与运行记录接口。

设计位置：[docs/design.md](../design.md) §1.1、§3、§4.3、§5、§7.2–7.3、§8③、§9。

直接前置：[#16](16.md)、[#24](24.md)、[#25](25.md)。

## 实施步骤

1. 为普通 apply 取得当次计划，为 --plan 按 ID 从目标存储取回审阅版本、内容对象、动作及其顺序。
2. 在目标机执行锁内复核仓库和主机绑定、相关能力及后端版本、输入摘要、前置条件与是否需要确认。执行前处理过期、缺失对象、未知动作及范围扩大的情形。
3. 开始执行时记录并输出 run_id，按依赖调用后端，跳过已达成的幂等动作，每次变更后重新观测。前置条件冲突或核验失败时记录资源和原因并停止依赖动作。
4. 让声明、参数与路径按类型传给后端，按动作需要在目标机取得权限。计划的默认保留期沿用存储策略。

## 实现与验证

本机 `dek apply --state-dir <目录>` 保存并执行当次规划。加 `--plan <ID>` 可加载固定审阅内容。执行开始输出 `run_id`，每个动作发布核验回执。超出审阅范围时保存并展示新计划，同一动作的前置条件冲突时在执行记录定位资源。锁、内容和重试约定见[执行复核决定](../adr/27-reviewed-local-apply.md)。

`cargo test --locked -p dek-cli --test apply` 通过正式 CLI 参数和文件探针验收。可用 `scripts/tests/local-apply` 把同一探针部署至 [#23](23.md) 的 Arch 来宾，以普通账户在临时状态根运行。现有本机文件规划后端会拒绝执行请求，生产文件变更由 [#31](31.md) 接入。

在 wks-lab 使用 #23 的工具环境，先构建探针，再构建来宾 CLI。

```bash
export CARGO_HOME=/data/dek-dev/cache/cargo
export CARGO_TARGET_DIR=/data/dek-dev/cargo/target/27-local-apply
export NIX_DONT_SET_RPATH_x86_64_unknown_linux_gnu=1
probe=$(
  cargo rustc --locked -p dek-cli --test apply --target x86_64-unknown-linux-gnu \
    --message-format=json -- -C link-arg=-Wl,--dynamic-linker=/lib64/ld-linux-x86-64.so.2 |
    jq -r 'select(.reason == "compiler-artifact" and .target.kind == ["test"] and .target.name == "apply") | .executable'
)
cargo rustc --locked -p dek-cli --bin dek --target x86_64-unknown-linux-gnu -- \
  -C link-arg=-Wl,--dynamic-linker=/lib64/ld-linux-x86-64.so.2
scripts/tests/local-apply v20261115.625457 \
  "$CARGO_TARGET_DIR/x86_64-unknown-linux-gnu/debug/dek" "$probe"
```


## 验收条件

- [x] 用探针后端规划两个相依的文件动作，执行后可读出两次核验且顺序与依赖一致。第二次 apply 对受管资源写入次数为 0。
- [x] 对源文件 A 规划后改仓库内容为 B，按原 ID 执行，目标得到 A。另建计划后手工写入目标内容 C，冲突信息指向该文件，执行保留 C。
- [x] 同时向同一目标提交两个 apply，探针观测到同一时间最多一个执行段。替换主机绑定或移除计划使用的能力时拒绝执行，仅新增无关能力时旧计划可用。
- [x] 用可注入的计划存储返回“已过期”，另用观测夹具扩大变更范围，两种情况都返回新计划 ID 供审阅，受管状态保持原样。注入未知动作或缺失内容对象，得到对应错误与重新规划提示。真实时钟过期和回收另由保留策略任务验收。
