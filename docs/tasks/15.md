# #15 用 dek show 追溯整机配置及单个 option 的生效来源

[GitHub Issue #15](https://github.com/xingjianxu/dek/issues/15) · Feature

- 分支：`issue-15-cli-show`
- Worktree：`/data/dek-dev/worktrees/15-cli-show/`

## 交付目标

让用户按主机查看已合并配置，并能追溯指定公开 option 的最终值及被覆盖的赋值。

## 范围与接口

在 `crates/dek-cli` 接入 `show [option]` 的文本、JSON、主机与仓库参数，在 `crates/dek-controller` 串联清单、声明图、schema 和合并。对显式使用的目标事实查询注入的提供者，SSH 查询与快照存储由相应组件接入。

设计位置：[docs/design.md](../design.md) §2.2–2.3、§5、§7.1–7.2、§8。

直接前置：[#12](12.md)、[#8](8.md)、[#9](9.md)、[#13](13.md)、[#10](10.md)。

## 实施步骤

1. 复用 `--repo`、`-H/--host` 和唯一的本地主机匹配，支持 JSON/Ruby 混合配置及用户注册的 schema。
2. 整机展示规范路径与生效值，指定路径时展示值、优先级、生效位置和被覆盖赋值。文本与 `--json` 消费同一份 `HostConfig`。
3. 将引用、schema 与 Ruby 错误定位到配置源，提供 `show --help`。目标事实有读取才查询，使用已有快照时显示来源。

## 验收条件

- [ ] 在示例仓库运行 `dek show services.caddy.enable -H server` 和 `dek show services.caddy.enable --host server --json`，两种输出显示相同最终值，均能定位 host 赋值和被覆盖的 profile。
- [ ] 用 Ruby 的 `user` 简写声明 Alice，在子目录运行 `dek show --json --repo <仓库> -H server`，输出使用完整 `users.users.alice` 路径。请求未知路径时报错并退出。
- [ ] 对未引用目标事实的主机执行 `show`，测试提供者调用次数为 0。对依赖目标架构的入口注入带标签的快照，显示目标值和快照来源。
