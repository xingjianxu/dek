# #49 通过 paru 以非 root 用户构建、安装和升级受管 AUR 包

[GitHub Issue #49](https://github.com/xingjianxu/dek/issues/49) · Feature

- 分支：`issue-49-arch-aur`
- Worktree：`/data/dek-dev/worktrees/49-arch-aur/`

## 交付目标

让计划列明受管 AUR 构建目标，保留 helper 的审阅与校验流程，并支持仓库升级后的独立恢复。

## 范围与接口

在 dek-linux::arch 实现 paru 适配器及其目标能力，接入补装、完整升级、显式重建、核验与执行记录。

设计位置：[docs/design.md](../design.md) §1、§5、§6、§7.2、§8⑤、§10.8。

直接前置：[#47](47.md)、[#46](46.md)、[#48](48.md)。

## 实施步骤

1. 在适用的仓库包事务完成后委托 paru 获取 PKGBUILD/源码、解析构建依赖、以非 root 身份构建并安装，保留原有 PKGBUILD 审阅和签名验证。交互通过独立终端通道。
2. 复用目标机适用的构建缓存，支持依赖系统库变化后的显式重建。通过本地包数据库复核结果，版本与构建信息仅用于事务和诊断。
3. 把已完成仓库事务和失败的具体 AUR 构建分别记录，重试时先核对实际状态，从仍未达成的目标继续。

## 实现与验证

本机有终端时，`apply` 可直接完成 paru 审阅。SSH 目标使用
`apply --interactive` 开启独立终端。同一运行可用 `--run <ID>` 续办。
`plan --rebuild-aur` 可与 `--upgrade` 组合，按计划 ID 执行。
[构建与续办决定](../adr/49-aur-build-and-recovery.md)

运行 `./scripts/check`。按 [#40](40.md) 构建本机和 Arch ABI 两份二进制后，用固定镜像复跑实机验收。

```bash
scripts/tests/arch-aur-fixture/prepare
scripts/tests/arch-aur-apply v20261115.625457 "$manager" "$guest_binary"
```

脚本复用外网关闭的 Arch 来宾、固定版本的 paru、签名仓库包和回环 AUR 源。每轮在 `runs/49/aur-apply.*` 保存原始计划、运行状态、交互终端、包事务和构建次数。夹具的静态库从 `1-1` 升到 `2-1`，同版本 AUR 重建的产物记录新库版本。

## 验收条件

- [x] 在有 paru 的 Arch 测试机规划并安装一个可控的受管 AUR 夹具，从构建记录核验 UID 非 0、审阅和签名流程仍可用，pacman -Q 能查到预期结果。
- [x] 升级受管包并显式触发一次依赖库变更后的重建，两次都能从计划看到具体构建目标。撤销包声明后仍可查询原包。
- [x] 移除 helper 或构建工具，计划指出缺项且没有开始仓库事务。模拟仓库升级成功、随后 AUR 构建失败，修复后重试仅构建失败目标，仓库升级调用次数保持为一。
