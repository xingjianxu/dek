# #36 按密文摘要和目标端验证结果规划 age 加密文件

[GitHub Issue #36](https://github.com/xingjianxu/dek/issues/36) · Feature

- 分支：`issue-36-age-secret-plan`
- Worktree：`/data/dek-dev/worktrees/36-age-secret-plan/`

## 交付目标

让计划在只公开密文元数据的条件下区分已知漂移、元数据修正与应用时核对。

## 范围与接口

在 dek-linux::secrets 实现目标端观测、路径校验与验证标记接口，向计划和诊断提供加密文件动作。

设计位置：[docs/design.md](../design.md) §2.3、§3、§4.3、§6.3、§8③。

直接前置：[#10](10.md)、[#14](14.md)、[#24](24.md)。

## 实施步骤

1. 接收管理端提供的密文内容摘要，在目标机解析 path、identityPaths、属主、属组和 mode，把计划绑定到已审阅的密文及这些设置。
2. 通过目标机受保护的验证标记判断受管明文的实际状态。无可用标记时返回“应用时核对”，把权限或属主漂移分开呈现。
3. 在计划的文本、JSON、验证与错误格式中统一使用密文元数据。将指定的受管文件与解密 identity 路径冲突归因到声明。

## 实现落点

- Linux 本机 `dek plan` 使用目标状态目录中的受保护标记。标记缺失或输入改变时显示“应用时核对”，仅属性漂移时生成独立动作。
- [验证标记决定](../adr/36-age-verification-markers.md)记录数据、路径检查和后续部署接口。

## 验收条件

- [x] 用测试标记分别表示已匹配、明文已被本地修改、标记缺失，计划依次呈现一致、漂移、应用时核对。仅改 mode 时列出权限修正。
- [x] 为同一个源密文在两台不同目标声明不同 identityPaths，计划绑定对应主机的路径与相同密文摘要。将落点设为 identity 自身时计划报错。
- [x] 解码测试产生的已保存计划与求值缓存，并检查终端诊断和 JSON，均找不到夹具私钥的已知明文标识。

`cargo test --locked -p dek-cli --test age_plan` 复现规划、标记、路径冲突和数据边界场景。同一组用例在 #23 独立 Arch 来宾中运行。
