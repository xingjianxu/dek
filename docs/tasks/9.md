# #9 把账户、目录与 systemd 选项展开为有关联的资源

[GitHub Issue #9](https://github.com/xingjianxu/dek/issues/9) · Feature

- 分支：`issue-9-builtin-system-modules`
- Worktree：`/data/dek-dev/worktrees/9-builtin-system-modules/`

## 交付目标

让用户通过规范 option 声明本地账户、组、目录及依赖对应账户的系统或用户级 unit。

## 范围与接口

在 `crates/dek-controller` 的内置 `modules` 实现用户、组、目录及 systemd 的 schema 与展开器，记录路径、类型及 dek 特有语义。目标账户解析、systemd manager 操作、linger 和密码策略不属于声明映射。

设计位置：[docs/design.md](../design.md) §2.2–2.3、§6.1、§6.2。

直接前置：[#7](7.md)。

## 实施步骤

1. 映射 `users.users.<name>` 的普通/系统账户、uid、group、extraGroups、home、shell、description 及 `users.groups.<name>.gid`，保留属性是否有声明。
2. 映射 `systemd.tmpfiles.settings.<config>.<path>.d` 的 `user`、`group`、`mode` 至目录资源，记录对账户与组的依赖，并保留字符串权限。
3. 为 `systemd.{services,timers}`、`systemd.user.{services,timers}` 及 `dek.users.<name>.systemd.{services,timers}` 记录对应作用范围、unit 名和账户引用。保留启用、运行及 timer 触发 service 的独立含义。

## 验收条件

- [ ] 用 JSON 声明 `research`、Alice 和 `/srv/research`，得到组、用户与目录三个资源。目录引用 Alice 与 research，`mode` 为 `0750` 字符串，未声明的 uid 和 home 保持未受管。
- [ ] 同时生成系统、Alice、Bob 的 `backup.timer`，三个资源可独立定位，Alice 的 unit 带 Alice 账户依赖。全局用户级定义可与指定账户的定义区分。
- [ ] 声明 `backup.service` 为 oneshot 并仅为配对 timer 声明启动和自启，资源集中两份 unit 均存在，持续运行期望仅在 timer 上。
