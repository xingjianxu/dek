# #12 用 Ruby DSL 采集规范 option 和可追踪的输入

[GitHub Issue #12](https://github.com/xingjianxu/dek/issues/12) · Feature

- 分支：`issue-12-ruby-declarations`
- Worktree：`/data/dek-dev/worktrees/12-ruby-declarations/`

## 交付目标

让 Ruby 入口与 JSON 使用同一 option 名称，并精确记录本次求值实际读取的输入。

## 范围与接口

在 `sdk/ruby` 实现声明及输入访问 API，在 `crates/dek-controller` 的 `eval` 接回 `UnitSpec` 与 Rust 的 profile 图。提供输入适配入口及依赖观测。HTTP 获取与 `refresh`、磁盘存储以及跨运行缓存命中判定由增量求值部分负责。

设计位置：[docs/design.md](../design.md) §2.1–2.3、§3.1、§4.2、§5、§6.2。

直接前置：[#11](11.md)、[#5](5.md)。

## 实施步骤

1. 实现 `profile`、`configure`、`service`、`group`、`user`、`directory` 等设计中的简写，规范化为完整路径并记录声明文件、行号与实际加载的代码（含 `require_relative`）。
2. 将 `source_file` 表示为声明文件相对的待部署引用，实现 `read_text`、受控环境、目录清单等读取回报。为所读目标事实、能力、缺失目标文件及声明的 HTTP 输入提供适配入口。
3. 让 Ruby 引用 JSON profile、JSON 引用 Ruby profile，引用图由 Rust 展开。将 `inputs: "sdk"` 与未声明可追踪约定的动态单元策略一并交给缓存层。

## 验收条件

- [ ] 用第 2.1、6.2 节的 Ruby 简写和等价 JSON 定义 Caddy、Alice 与目录，忽略来源表示后得到相同 option 路径和值。Ruby 端保留简写所在行号。
- [ ] 让 Ruby 主机引入 JSON profile，再由该 profile 引入 Ruby 文件，Rust 可还原完整来源链。修改 `require_relative` 的帮助文件后新采集的代码依赖摘要改变。
- [ ] 分别用 `source_file` 与 `read_text` 引用相同文件，前者仅记录部署来源，后者报告求值内容依赖。测试目录成员、环境值和缺失目标文件各自形成可区分的输入记录。
- [ ] 比较使用原生 Ruby I/O 的默认动态入口与标记 `inputs: "sdk"` 的入口，输出携带不同的复用策略。目标事实缺失时可定位到读取处，未取用管理机事实。
