# #25 按 run_id 持久化动作结果和待重试服务通知

[GitHub Issue #25](https://github.com/xingjianxu/dek/issues/25) · Feature

- 分支：`issue-25-target-run-store`
- Worktree：`/data/dek-dev/worktrees/25-target-run-store/`

## 交付目标

让不同进程能从目标机恢复一次执行的已完成、失败、结果不明动作和待重试项。

## 范围与接口

在 `dek-target::state` 提供与仓库、目标和计划关联的运行记录，以及查询最近/指定执行的接口。存储暴露状态变更原语，执行器负责动作派发、状态核验和重试。

设计位置：[docs/design.md](../design.md) §4.2、§4.3、§5、§6、§7.2。

直接前置：[#24](24.md)。

## 实施步骤

1. 在执行开始时建立唯一 `run_id`，保存计划引用与稳定动作标识，提供按当前目标读取指定或最近一次执行的接口。
2. 持久化动作尝试、已完成、已失败和结果待核验状态，支持在文件替换前写入待处理的服务通知、在服务动作成功后确认完成。
3. 对同一执行请求及同一结果更新提供一致的读回结果。写入中断时能够区分结果待核验与已提交的完成状态。记录保留运行或恢复需要的内容引用。

## 验收条件

- [ ] 建立两个执行记录，在新进程中查询最近一次和按 ID 查询旧记录。均返回正确目标、计划及各自动作，不会混用仓库或主机。
- [ ] 在持久化动作开始后、写入成功回执前终止进程，再打开状态存储，该动作显示结果待核验。重复记录同一次成功回执，查询只显示一项已完成动作。
- [ ] 预先登记服务通知并模拟服务失败，删除管理机缓存再查询，通知及计划引用仍在。提交恢复成功结果后不再列为待重试。

提交与 PR 验证按[协作约定](../../AGENTS.md)执行。
