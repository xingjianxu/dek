# #39 验收本机离线应用、漂移修复与撤销管理

## 交付目标

以真实 Arch 目标机证明同一配置可离线收敛，重复执行不会写受管对象或多次重载服务。

## 范围与接口

在 dek-cli 端到端集成用例中复用专用 Arch VM，用目标机本机 CLI 和可计数的测试服务验证阶段③。

设计位置：[docs/design.md](../design.md) §2.2、§6、§7.3–7.4、§8③、§10.6、§10.8。

直接前置：[#23](23.md)、[#38](38.md)、[#33](33.md)。

## 实施步骤

1. 准备已安装依赖包及运行中服务的测试机，切断外网后以本机入口规划和应用一份有文件及服务联动的配置。
2. 记录受管文件摘要、写入观察值、服务通知计数和包安装状态，连续执行两次，再手工修改文件重跑 plan/apply。
3. 撤销整段包、文件和服务声明并重跑。将建机条件、CLI 输出与目标状态断言纳入可重复运行的用例。

## 验收条件

- [x] 断网时第一次 apply 写入配置，服务仅重载一次。第二次 plan 为零变更，第二次 apply 对受管文件写入及服务重载计数均为 0。
- [x] 手工修改已部署文件后，plan 指出正确的目标和触发服务，apply 复原，再次规划为零变更。
- [x] 撤销包、文件和运行中服务的声明后 apply，pacman 查询、文件摘要、systemd 启用和运行状态均保持原样。

## 复现方式

在 wks-lab 按 [#23](23.md) 准备已验证镜像，并将 `CARGO_TARGET_DIR` 设为本任务目录后构建来宾版 `dek`。

```bash
scripts/tests/local-convergence v20261115.625457 "$binary" "$ripgrep_archive"
```

`ripgrep_archive` 指向已缓存的 Arch x86_64 ripgrep 软件包归档，旁边须有其 `.sig` 文件。脚本复用开发机已安装的 Ruby Nix 闭包，通过来宾 Arch keyring 验签预装 ripgrep。QEMU 在整轮启用 `restrict=on`，仅通过回环端口进行 SSH 管理。

首次应用和漂移修复使用 `apply --plan`，重复应用和撤销声明使用普通 `apply`。日志记录 JSON 计划、实际变更数、文件摘要和 stat、服务 reload 计数、包数据库记录与服务状态。成功收尾清理本轮差分盘，证据保存在 `/data/dek-dev/runs/39/`。
