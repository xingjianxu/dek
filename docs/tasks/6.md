# #6 按公共 schema 合并 option 并保留冲突和覆盖来源

[GitHub Issue #6](https://github.com/xingjianxu/dek/issues/6) · Feature

- 分支：`issue-6-option-schema-merge`
- Worktree：`/data/dek-dev/worktrees/6-option-schema-merge/`

## 交付目标

将模块默认值、profile 与 host 赋值合并成可追溯的 `HostConfig`，向各语言提供相同校验结果。

## 范围与接口

在 `crates/dek-controller` 的 `modules` 加载静态 schema、注册完整 option 路径并实现合并，在 `dek-core` 复用来源与类型模型。通过输入 `UnitSpec` 独立测试，CLI 展示和资源展开各自消费结果。

设计位置：[docs/design.md](../design.md) §2.2、§2.3、§3、§8。

直接前置：[#2](2.md)。

## 实施步骤

1. 定义 schema 的类型、默认值、合并策略和说明，支持命名子项（如 `users.users.<name>`）与保留原拼写的自由键映射（如 Git 配置）。
2. 执行模块默认值 → profile → host 的优先级，同层相同标量可合并，按各自策略对集合列表去重、为有序列表保序。
3. 保留生效定义和被覆盖定义，诊断未知路径、类型错误、同级标量冲突。重复注册同一 option 定义时列出两个模块及其定义位置。

## 验收条件

- [ ] 给 `services.caddy.enable` 设置默认 `false`、profile `true` 和 host `false`，最终为 `false`，来源链能还原三层赋值。
- [ ] 让两个同级 profile 对同一标量先给相同、再给不同布尔值，前者成功，后者报错并列出双方文件及具体位置。
- [ ] 为集合型包列表和测试用有序列表各输入重复或顺序不同的数据，对应结果分别满足 schema 去重规则和顺序规则。
- [ ] 分别试用未知 option、错误类型及重复 schema 定义，诊断给出完整路径和相关来源。`programs.git.config.init.defaultBranch` 所在映射保留 `defaultBranch` 的大小写。

提交与 PR 验证按[协作约定](../../AGENTS.md)执行。
