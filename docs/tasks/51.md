# #51 用仅支持文件的内存目标和 Arch 验证跨平台规划边界

[GitHub Issue #51](https://github.com/xingjianxu/dek/issues/51) · Task

- 分支：`issue-51-platform-capabilities`
- Worktree：`/data/dek-dev/worktrees/51-platform-capabilities/`

## 交付目标

以同一份 profile 和规划管线验证资源能力、目标路径语义及旧计划兼容性均由目标决定。

## 范围与接口

在 `crates/dek-target/tests` 和相应的 `crates/dek-cli/tests` 注册仅支持文件的内存后端，以已注册的 Arch 文件与 systemd 能力作对照。用受控观测运行共享配置，涉及真实 Arch 主机状态的部分按已有集成入口在专用 VM 验证。

设计位置：[docs/design.md](../design.md) §1.1、§3.1、§5、§8 跨平台接口验收、§9。

直接前置：[#16](16.md)、[#31](31.md)、[#32](32.md)。

## 实施步骤

1. 为内存目标提供文件类型、版本与支持字段，自定义与 Linux 管理机不同的目标路径规则。双方共用 `ResourceSet`、规划入口和同一份按目标能力导入的 profile。
2. 分别覆盖显式不支持的类型及字段、混合合法/非法声明、条件导入，断言准确的主机与声明来源，以及整份计划的失败语义。
3. 使用相同管理机源文件分别走两个目标。注入目标路径别名和能力变动，对比已用与无关能力对原计划复核的影响。

## 验收条件

- [ ] 在 Linux 运行共享 profile 夹具，Arch 有 systemd 能力时产生 timer，文件内存目标跳过该导入且保留文件。直接声明 timer 时错误含主机与配置位置，合法文件也没有可执行动作。
- [ ] 让内存目标使用 `C:\Apps\demo.conf` 一类目标路径及其平台别名。管理端传输原始拼写，目标端按自己的规则识别同一路径并检测冲突。管理端仓库源文件仍按 Linux 路径读取。
- [ ] 用文件后端生成原计划后增加无关能力，原计划复核通过。撤销所用文件属性或换成不兼容的后端版本，原计划在任何执行动作前被拒绝。
