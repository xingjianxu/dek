# #40 通过 OpenSSH 启动目标端并核对主机身份和能力

[GitHub Issue #40](https://github.com/xingjianxu/dek/issues/40) · Feature

- 分支：`issue-40-ssh-handshake`
- Worktree：`/data/dek-dev/worktrees/40-ssh-handshake/`

## 交付目标

让管理端仅在 OpenSSH 验证和 dek 握手均通过后，向绑定的兼容目标分派请求。

## 范围与接口

在 `dek-core` 定义目标端握手与结构化请求，`dek-controller::transport` 管理 OpenSSH 子进程，`dek-cli` 提供按次启动的内部目标入口，并与本机适配器共用同一套请求语义。

设计位置：[docs/design.md](../design.md) §1.1、§5、§7.1、§9。

直接前置：[#4](4.md)、[#14](14.md)、[#23](23.md)。

## 实施步骤

1. 使用清单指定的 SSH 别名调用系统 OpenSSH，复用其身份、agent 和主机密钥配置。远端命令为固定的 dek 内部入口。
2. 让目标端报告绑定标识、系统、发行版、架构、协议版本及各资源能力/版本，协商兼容版本并在派发业务请求前核对目标标识。
3. 关联结构化请求与回复，区分远端诊断与协议数据。让包名、路径等资源字段只作为请求数据传输，将目标路径按原始格式交给目标端处理。
4. 对缺少二进制、协议版本不兼容、SSH 失败及目标不匹配分别返回可定位的阶段、别名和目标信息。

## 实现与验证

`dek target-info -H <host> [--json]` 从本机或绑定的 SSH 目标报告系统信息、协议版本和资源能力。清单继续使用 `target.ssh`。逻辑主机名与目标系统主机名不同时，用同一 host 项的 `targetId` 显式绑定。连接与协议约定见 [SSH 握手决定](../adr/40-ssh-target-handshake.md)。

执行 workspace 检查。实机测试复用 [#23 的 Arch 环境](23.md) 和 Arch ABI 构建方式，同时需要管理机本地构建。

```bash
export CARGO_HOME=/data/dek-dev/cache/cargo
export CARGO_TARGET_DIR=/data/dek-dev/cargo/target/40-ssh-handshake
cargo build --locked -p dek-cli --bin dek
NIX_DONT_SET_RPATH_x86_64_unknown_linux_gnu=1 \
  cargo rustc --locked -p dek-cli --bin dek --target x86_64-unknown-linux-gnu -- \
  -C link-arg=-Wl,--dynamic-linker=/lib64/ld-linux-x86-64.so.2
scripts/tests/ssh-handshake v20261115.625457 \
  "$CARGO_TARGET_DIR/debug/dek" "$CARGO_TARGET_DIR/x86_64-unknown-linux-gnu/debug/dek"
```

wks-lab 的双机验收使用各轮预置的主机公钥，核对错绑与已知主机密钥错误的诊断。版本 99 的测试端只收到握手帧。实际 OpenSSH 的启动参数和协议回传均由脚本校验。

## 验收条件

- [x] 通过已配置的测试别名运行握手，从本机与进程适配器读取同一测试后端，得到相同的版本及能力集合。
- [x] 把同一别名切到另一台受信任测试目标，或让目标报告不兼容版本。均在发送资源/执行请求前报错。修改测试 known_hosts 为不匹配记录，连接也失败。
- [x] 在结构化请求中回送含空格和引号的测试路径并观察启动参数。字节与目标收到的路径一致，SSH 远端命令部分保持固定。
