# #40 通过 OpenSSH 启动目标端并核对主机身份和能力

[GitHub Issue #40](https://github.com/xingjianxu/dek/issues/40) · Feature

- 分支：`issue-40-ssh-handshake`
- Worktree：`/data/dek-dev/worktrees/40-ssh-handshake/`

## 交付目标

让管理端仅在 OpenSSH 验证和 dek 握手均通过后，向绑定的兼容目标分派请求。

## 范围与接口

在 `dek-core` 定义目标端握手与结构化请求，`dek-controller::transport` 管理 OpenSSH 子进程，`dek-cli` 提供按次启动的内部目标入口，并与本机适配器共用同一套请求语义。

设计位置：[docs/design.md](../design.md) §1.1、§5、§7.1、§9。

直接前置：[#4](4.md)、[#14](14.md)、[#23](23.md)。

## 实施步骤

1. 使用清单指定的 SSH 别名调用系统 OpenSSH，复用其身份、agent 和主机密钥配置。远端命令为固定的 dek 内部入口。
2. 让目标端报告绑定标识、系统、发行版、架构、协议版本及各资源能力/版本，协商兼容版本并在派发业务请求前核对目标标识。
3. 关联结构化请求与回复，区分远端诊断与协议数据。让包名、路径等资源字段只作为请求数据传输，将目标路径按原始格式交给目标端处理。
4. 对缺少二进制、协议版本不兼容、SSH 失败及目标不匹配分别返回可定位的阶段、别名和目标信息。

## 验收条件

- [ ] 通过已配置的测试别名运行握手，从本机与进程适配器读取同一测试后端，得到相同的版本及能力集合。
- [ ] 把同一别名切到另一台受信任测试目标，或让目标报告不兼容版本。均在发送资源/执行请求前报错。修改测试 known_hosts 为不匹配记录，连接也失败。
- [ ] 在结构化请求中回送含空格和引号的测试路径并观察启动参数。字节与目标收到的路径一致，SSH 远端命令部分保持固定。
