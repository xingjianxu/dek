# #18 按实际读取的输入复用声明采集结果

[GitHub Issue #18](https://github.com/xingjianxu/dek/issues/18) · Feature

- 分支：`issue-18-cache-collect-inputs`
- Worktree：`/data/dek-dev/worktrees/18-cache-collect-inputs/`

## 交付目标

在不漏掉输入变化的前提下，让静态声明和显式标记 `inputs: "sdk"` 的 Ruby 单元跨运行命中。

## 范围与接口

在 `dek-controller::eval` 与 `cache` 对接 JSON/Ruby 采集、SDK 的依赖记录和目标事实提供接口。目标事实先以测试适配器覆盖，SSH 实现可随后接入。

设计位置：[docs/design.md](../design.md) §3.1、§4.1、§4.2、§5。

直接前置：[#17](17.md)、[#5](5.md)、[#12](12.md)。

## 实施步骤

1. 从选定 host 出发按需访问声明，记录入口、实际加载代码与运行时／SDK 签名。profile 引用单独存放，使被引用 profile 的内容变化按其自身单元检查。
2. 以输入种类和标识重读 SDK 记录的文件内容、环境变量、目录成员及显式目标事实/能力/文件。记录缺失状态，含目标输入的单元按已绑定主机隔离，发现新的目标依赖时也正确更新键的适用范围。
3. 静态单元及 `inputs: "sdk"` 的动态单元通过校验后复用。未作该声明的 Ruby 单元每次重新求值。协议或校验失败时退出并保留上一份成功结果。
4. 保持 `source_file` 的被引用内容与 Ruby 主动读取内容的依赖语义，替换每次成功采集的依赖清单。

## 验收条件

- [ ] 连续运行使用原生 I/O 的未标记单元和只用 SDK 的已标记单元。前者两次进入求值器，后者第二次直接命中。
- [ ] 分别修改加载的 Ruby 文件、已读环境变量、目录成员名，并让原先缺失的目标文件出现。每次只使相应读取者失效。
- [ ] 两台主机对同一路径返回不同文本。读取该文件的单元结果各自正确，两台主机对同一无目标依赖的 profile 可复用结果。
- [ ] 故意引入 Ruby 语法错误并执行规划。命令带来源失败，错误结果没有替换原缓存。

提交与 PR 验证按[协作约定](../../AGENTS.md)执行。
