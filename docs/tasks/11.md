# #11 通过可复用的 Ruby 子进程收发版本化求值请求

[GitHub Issue #11](https://github.com/xingjianxu/dek/issues/11) · Feature

- 分支：`issue-11-ruby-evaluator`
- Worktree：`/data/dek-dev/worktrees/11-ruby-evaluator/`

## 交付目标

让一次 dek 运行中的 Ruby 单元复用同一子进程，并能按请求关联结果、查询目标信息和定位故障。

## 范围与接口

在 `crates/dek-core` 定义语言协议，在 `crates/dek-controller` 的 `eval` 管理进程，在 `sdk/ruby` 提供随 CLI 分发的协议入口。提供 collect/expand 分派与测试处理器，DSL、模块展开逻辑及跨运行缓存各自由调用方接入。

设计位置：[docs/design.md](../design.md) §1、§3.1、§5、§9。

直接前置：[#2](2.md)。

## 实施步骤

1. 实现每行一条紧凑 JSON 的 v1 协议，关联 `protocolVersion`、请求 ID、操作名、负载和结果，日志统一走 stderr。
2. 延迟启动管理机 Ruby，对一次运行的多次 `collect`、`expand` 复用进程并隔离单元上下文。纯 JSON 路径保持零次 Ruby 启动。
3. 处理与父请求相关的目标事实、能力和 `target.read_text` 反向请求，支持注入数据提供者。版本错误、非法输出、语法错误、运行异常与子进程退出产生阶段及可得源码位置。

## 验收条件

- [x] 通过协议测试在同次运行发出两次 `collect` 和一次 `expand`，收到匹配各自 ID 的结果，只启动一次 Ruby，前一单元状态不串入后一单元。
- [x] 用测试提供者应答两个不同目标查询，结果归属正确请求并留下输入记录。Ruby 打印到 stderr 的内容不影响下一帧解码。
- [x] 分别使用坏版本、格式错误的响应和 Ruby 语法错误夹具，整次求值失败，给出阶段及可取得的文件/行号，不返回可写入成功缓存的输出。

wks-lab 的 Ruby 3.4.12 验证了请求复用、反向事实与缺失观测、协议故障、加载文件报错和管道收尾。配置中的 stdout 转到 stderr，工作目录和环境变量在每次求值后恢复。
