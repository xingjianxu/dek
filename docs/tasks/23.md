# #23 从只读基盘按轮启动、重启与收尾 Arch 测试虚拟机

[GitHub Issue #23](https://github.com/xingjianxu/dek/issues/23) · Task

- 分支：`issue-23-arch-vm-harness`
- Worktree：`/data/dek-dev/worktrees/23-arch-vm-harness/`

## 交付目标

让开发机从已验证的只读 Arch cloudimg 启动可独立重启、部署和收尾的 QEMU/KVM 测试目标。

## 范围与接口

在 `scripts/` 增加镜像与集成环境入口，定义 cloud-init 模板、测试专用 SSH 身份和证据目录。镜像、差分盘、密钥及日志均放在 `/data/dek-dev/`。包/AUR 测试联网方式留给对应策略决定。

设计位置：[docs/design.md](../design.md) §9.1、§10.6、§10.7、§10.8、§11。

直接前置：[#22](22.md)。

## 实施步骤

1. 检查 x86_64 Linux、QEMU/KVM 工具及 /dev/kvm 访问，按镜像标识选择已验证的只读基盘。
2. 在 `runs/<issue>/<run>/` 生成 qcow2 差分盘、cloud-init 和串口日志，分配独立实例标识及绑定 `127.0.0.1` 的 SSH 端口。默认 2 vCPU、2 GiB，允许 AUR 场景调高。
3. 等待 cloud-init 完成和 SSH 可用后部署本轮已构建的 `dek`，支持同一轮重启保留磁盘。记录镜像、构建版本、端口、实例、命令与日志的位置。 在 Arch 来宾实际运行 dek --version，验证构建产物的动态加载器及运行库兼容。
4. 按本轮归属关闭实例。成功可清理差分盘，失败保留盘与日志供复查，应对启动失败、中途退出和同时运行多个实例。

## 验收条件

- [ ] 从同一基盘同时启动 A、B，在 A 写入哨兵文件并重启。A 仍有哨兵，B 无此文件，端口仅监听回环地址且互异，基础镜像摘要不变。
- [ ] SSH 进入来宾核对测试部署的 dek 与指定构建一致。正常结束后按配置清理差分盘，故意失败的轮次保留本轮差分盘和日志，其他实例及基盘仍可用。
