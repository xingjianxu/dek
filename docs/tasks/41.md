# #41 在远程规划时从绑定目标复核显式读取的事实

[GitHub Issue #41](https://github.com/xingjianxu/dek/issues/41) · Feature

- 分支：`issue-41-ssh-target-facts`
- Worktree：`/data/dek-dev/worktrees/41-ssh-target-facts/`

## 交付目标

让按需请求的目标事实、能力与目标文件参与求值和缓存，并使正式规划基于目标当前值。

## 范围与接口

在 `dek-controller::transport` / `eval` 与 `dek-target` 接入 `target.fact(...)`、`target.read_text(...)`、能力查询和按主机隔离的快照。Ruby 普通文件读仍由管理机处理。

设计位置：[docs/design.md](../design.md) §1.1、§3.1、§4.2、§5、§7.2。

直接前置：[#40](40.md)、[#18](18.md)。

## 实施步骤

1. 将 SDK 已有的反向请求映射到当前握手目标，分别记录事实名或目标路径、主机标识和观测摘要，包括可区分的缺失文件结果。
2. 在允许跨主机预览使用快照的路径上标明快照来源，隔离各目标的记录。缺失值或不可读结果遵循该请求的失败语义并保留来源。
3. 正式规划重查已用事实及能力，按当前值决定缓存是否可用。未访问的目标信息不构成该单元的依赖。

## 实现与验证

`dek show -H <host>` 按声明连接绑定的目标。`dek show --target-snapshot -H <host>` 离线读取快照，在文本及 JSON 输出标明来源。正式的 `dek plan -H <host>` 通过规划连接实时复核所用输入。实时求值和采集缓存复核共用 `RemoteTarget`，远端计划请求的装配见 [#42](42.md)。详见[目标输入与快照决定](../adr/41-ssh-target-inputs.md)。

CLI 测试覆盖结构化请求、两台目标的独立快照、绑定变更、缺失文件出现及目标事实错误。使用 [#40 的构建方式](40.md) 构建管理端和 Arch ABI 目标端，运行双机验收。

```bash
scripts/tests/ssh-target-inputs v20261115.625457 \
  "$CARGO_TARGET_DIR/debug/dek" "$CARGO_TARGET_DIR/x86_64-unknown-linux-gnu/debug/dek" --plan
```

## 验收条件

- [x] 在管理机和目标机为同一路径写不同文本，普通本地读取返回管理机值，`target.read_text` 返回目标机值。两台目标主机各自保留正确来源。
- [x] 以记录的快照完成一次可用的预览，输出标明快照来自何处。改变远端文件再正式 `plan`，使用新值且只使读取者失效。
- [x] 让已用的远端事实在正式规划时不可取得，同时在管理机提供同名值。规划返回目标事实诊断。让先前不存在的目标文件出现后，读取它的缓存失效。
