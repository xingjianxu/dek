# #29 创建 Linux 本地用户和组并修正声明的账户属性

[GitHub Issue #29](https://github.com/xingjianxu/dek/issues/29) · Feature

- 分支：`issue-29-linux-accounts`
- Worktree：`/data/dek-dev/worktrees/29-linux-accounts/`

## 交付目标

在目标机按名称管理普通用户、系统账户与组，并让后续资源使用系统实际分配的 UID/GID。

## 范围与接口

在 dek-linux::accounts 注册组与用户后端，实现本地和外部名称解析、创建、属性差异、执行和复读。

设计位置：[docs/design.md](../design.md) §2.3、§6.2、§8③、§9、§11。

直接前置：[#9](9.md)、[#27](27.md)、[#23](23.md)。

## 实施步骤

1. 比对本地账户数据库与目标机名称服务的解析结果，检查同名外部条目、重复数字 ID、已有对象显式 UID/GID 不符及组依赖缺失，归因到声明。
2. 为普通账户和组生成对应的 useradd/usermod、groupadd 等动作，按系统账户需求接入 systemd-sysusers 等创建工具，先准备主组及附加组。
3. 已有账户仅调整声明过的字段，附加组按增量添加。修改 home 字段时保留原目录数据。创建后重新解析用户名和组名，再交给下游资源。
4. 在账户模块编码前按 §11 确认密码哈希与锁定状态是否纳入首版，并记录决定及其与加密机制的关系。

## 验收条件

- [ ] 在 Arch 测试机声明 research 组、普通用户 alice 和一个系统服务账户，验证 getent/id 的名称、组及已声明属性，第二次 plan 为零动作。
- [ ] 给 Alice 手工增加其他附加组，修改受管 shell 后 apply，仅 shell 被修正，原附加组继续存在。更改 home 字段时旧目录内的标记文件仍在原处。
- [ ] 以名称服务夹具提供同名外部条目，并分别夹入已占用的 UID/GID 与现有同名对象的 ID 差异。各场景 plan 定位冲突，系统账户数保持不变。
- [ ] 撤销账户声明后再 apply，getent 仍可查询原对象，home 中数据仍可读取。
