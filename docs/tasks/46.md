# #46 在与现有系统一致的事务中自动补装缺少的仓库包

[GitHub Issue #46](https://github.com/xingjianxu/dek/issues/46) · Feature

- 分支：`issue-46-arch-package-install`
- Worktree：`/data/dek-dev/worktrees/46-arch-package-install/`

## 交付目标

让普通 apply 安装确实缺失的官方仓库包及其依赖，再继续应用依赖这些包的配置。

## 范围与接口

在 dek-linux::arch 实现 pacman 补装事务与本地包缓存选择，向目标执行器提供事务范围和核验条件。

设计位置：[docs/design.md](../design.md) §3、§6、§7.2、§7.4、§8⑤。

直接前置：[#45](45.md)、[#27](27.md)。

## 实施步骤

1. 从本地缺包状态开始，用 pacman 后端解析所需包和依赖，确认能与当前系统一致地单独安装。
2. 把版本与包清单纳入计划，优先复用与事务匹配的本地包文件，仅为缺失文件按需获取内容。
3. 执行前复核事务范围与版本，按计划安装并用本地包数据库核验，随后运行依赖的配置动作；需要刷新或兼容性存疑时转入完整升级预览。

## 使用和验证

当本机同步数据库能够确认可独立补装时，`dek plan --json` 列出缺少的仓库包、依赖和候选版本。以目标端 root 运行普通 `dek apply` 即可补装，核对包版本，然后才验证并部署依赖它们的配置。执行前发现候选或范围已变时，命令保存新 `plan_id` 等待审阅。归档、锁和签名策略见[原生补装事务 ADR](../adr/46-guarded-arch-package-install.md)。

使用 `scripts/tests/arch-package-install <镜像标识> <Arch 兼容的 dek 构建>`。脚本在外网关闭的 Arch 来宾生成并签署测试仓库和软件包，通过回环 HTTP 记录下载。完整缓存场景关闭软件源。部分缓存场景含同名错误归档和后续目录中的正确归档。依赖配置写入由被安装包创建的目录，原生 hook 核对包内容已出现且配置仍待部署。 [测试软件源策略](https://github.com/xingjianxu/dek/issues/46#issuecomment-7087119117)

## 验收条件

- [x] 在状态与仓库一致的 Arch 测试机声明一个缺包及依赖它的配置。plan 列出包及所需依赖，普通 apply 完成补装后才部署配置，pacman -Q 可查到新包。
- [x] 为相同事务预置所有匹配包文件后断网，补装成功。另一次仅移除一个缓存文件，下载记录只出现缺少的内容。
- [x] 预览后改变候选版本或引入新的事务包，执行原计划返回新 ID 并保留当前系统状态。
