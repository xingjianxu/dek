# #35 维护用户声明的 SSH 授权公钥并保留手工条目

[GitHub Issue #35](https://github.com/xingjianxu/dek/issues/35) · Feature

- 分支：`issue-35-ssh-authorized-keys`
- Worktree：`/data/dek-dev/worktrees/35-ssh-authorized-keys/`

## 交付目标

让目标用户的 SSH 授权可由内联公钥及仓库公钥文件共同维护，同时区分清空受管集合与撤销管理。

## 范围与接口

在 dek-linux 的账户与文件后端处理已规范化的 authorizedKeys.keys 和 keyFiles，按目标账户合并授权条目。

目标端使用已审阅的内容对象生成带 dek 标记的受管块，和本地账户的 `.ssh/authorized_keys` 合并。块外字节保持原样。已有手工条目与受管公钥重复、路径指向符号链接或标记无法配对时报错。

设计位置：[docs/design.md](../design.md) §2.3、§6.2–6.3、§8③。

直接前置：[#29](29.md)、[#31](31.md)、[#10](10.md)。

## 实施步骤

1. 将内联条目与 keyFiles 的已审阅内容统一为该用户的期望集合，解析目标账户及 home，建立账户和目录依赖。
2. 在目标端区分既有手工条目与 dek 所管理的条目，增删受管集合时保留手工条目及其原有选项。
3. 安全更新授权文件并复读验证。显式空列表清除受管条目，省略整个资源时保留现有条目。

## 验收条件

- [x] 预置 Alice 的手工公钥，声明一把内联公钥和一把文件公钥。apply 后三者均在，重复 apply 时授权文件未被重写。
- [x] 把受管列表改为空后 apply，手工条目及其原有选项保留。另在已部署场景直接撤销资源，原有受管与手工条目均保留。
- [x] 在同时存在 Alice 和 Bob 的目标机上修改 Alice 的 keyFiles，apply 后仅 Alice 获得新条目。
- [x] 保存计划后修改仓库公钥文件，指定原计划 apply 仍使用原审阅内容。同批声明创建账户和目录时，先创建账户及目录，再发布授权文件。
- [x] Arch OpenSSH 接受 Alice 的受管公钥、拒绝用于 Bob 的同一公钥，并在清空后继续执行手工公钥的强制命令。

独立 Arch 来宾已验证上述场景。实机验收可运行 `scripts/tests/ssh-authorized-keys <已校验镜像 ID> <Arch 兼容 dek 二进制>`。
