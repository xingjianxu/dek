## 交付目标

为声明采集与合并建立跨语言可序列化的模型，保留定义和覆盖来源。

## 范围与接口

在 `crates/dek-core` 定义声明与配置模型，提供 JSON/Ruby 共用的序列化夹具。资源、动作和计划另卡交付。

设计位置：[docs/design.md](../design.md) §1.1、§2.2、§3、§3.1、§4.3、§9。

直接前置：[#1](1.md)。

## 实施步骤

1. 定义规范 option 路径、Ruby 文件与行号、JSON Pointer、profile 引用及其参数、读取的输入与缺失观测，组成 `UnitSpec`。
2. 用 HostConfig 表示生效值、优先级、全部来源及被覆盖赋值。
3. 为两种来源类型、显式缺失观测与嵌套 profile 参数建立往返夹具。

## 模型与夹具

- `UnitSpec` 记录逐条赋值、带嵌套参数的 profile 引用及输入观测。路径保留规范名的大小写。Ruby 来源使用 `file` 和从 1 起算的 `line`，JSON 来源使用 `file` 和 `pointer`。协议示例中的裸 profile 名称仍可读入，带参数和位置的引用使用 `name`、`params` 和 `origin` 对象字段。输入观测以 `{"digest": "..."}` 或 `"missing"` 表示。[UnitSpec 夹具](../../crates/dek-core/tests/fixtures/unit-spec.json)
- `HostConfig` 按 option 路径记录生效值、优先级、生效定义及被覆盖定义。控制端按模块默认值、profile 和 host 顺序标注逐条定义的优先级。[HostConfig 夹具](../../crates/dek-core/tests/fixtures/host-config.json) · [合并规则 #6](6.md)
