# #33 合并文件触发的服务通知并重试失败的重载

[GitHub Issue #33](https://github.com/xingjianxu/dek/issues/33) · Feature

- 分支：`issue-33-service-notifications`
- Worktree：`/data/dek-dev/worktrees/33-service-notifications/`

## 交付目标

让同一服务收到一次必要的 reload 或 restart，并在文件已更新但服务通知失败时继续完成该通知。

## 范围与接口

在 dek-target::planner/executor 编排文件触发关系与待办，通过 dek-linux::systemd 执行通知，复用目标运行记录。

设计位置：[docs/design.md](../design.md) §3、§4.3、§6、§7.3、§8③⑤。

直接前置：[#28](28.md)、[#32](32.md)。

## 实施步骤

1. 按目标 manager 和完整 unit 名归并同批通知，保持配置校验、替换、daemon-reload 与服务通知的依赖顺序。
2. 替换前登记通知，区分已登记和配置已生效的状态；中断恢复时核对目标内容与关联动作，确认替换生效后才能发送通知。
3. 首次启动已加载新配置的服务时省略重复 reload，校验失败或文件未生效时中止相关通知，记录可定位的失败原因。
4. 把 reload/restart 的明确失败保留到下次规划，执行成功后清除待办。结果不明时沿用运行恢复所定义的核验流程。

## 验收条件

- [ ] 在 Arch 测试机修改两个触发同一已运行服务的文件，执行后该服务计数器只增加一次。首次启动场景无额外 reload。
- [ ] 注入只失败一次的 ExecReload，第一次 status 显示文件已落盘和服务待重试。文件内容已一致时 plan 仍列出重载，再次 apply 只补这一项。
- [ ] 在通知登记后、替换前中断，并在另一次场景中于替换后、通知前中断。恢复核对内容，旧配置不会触发新通知，已落盘的配置最终收到一次通知。
