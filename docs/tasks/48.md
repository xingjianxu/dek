# #48 在计划中列出受管 AUR 候选并报告构建环境缺项

[GitHub Issue #48](https://github.com/xingjianxu/dek/issues/48) · Feature

- 分支：`issue-48-arch-aur-preview`
- Worktree：`/data/dek-dev/worktrees/48-arch-aur-preview/`

## 交付目标

在任何包写入前明确目标所需的 AUR 构建及可用能力。

## 范围与接口

在 dek-linux::arch 实现 paru 查询与预检，把计划清单接入仓库升级预览；本卡止于只读规划。

设计位置：[docs/design.md](../design.md) §1、§5–6、§7.2、§8⑤。

直接前置：[#45](45.md)。

## 实施步骤

1. 在目标机预检 helper、构建工具和非 root 构建环境，按来源列出受管 AUR 候选及构建依赖，给完整升级预览提供构建清单。
2. 从声明的 AUR 来源和目标本地数据库筛出受管包，生成构建目标与原因，纳入已审阅计划。
3. 分别报告 helper、构建工具或非 root 构建用户缺失，并保留包的配置来源。

## 验收条件

- [x] 用受控源规划一个缺少的和一个已安装待升级的受管包，列表准确给出两个构建目标。未受管包保持原样。
- [x] 移除 paru 或构建环境后重新规划，诊断指明缺项且系统软件包数据库、受管配置均保持原样。

## 验证命令

- `cargo test --locked -p dek-linux arch::aur::tests` 覆盖 paru 候选的来源、版本、续行依赖及重复记录。
- 在开发机运行 `scripts/tests/arch-aur-fixture/prepare`，校验固定的 paru v2.2.1 发布归档与 Arch Linux Archive 软件包。按 [#23](23.md) 生成 Arch ABI 二进制后执行 `scripts/tests/arch-aur-plan v20261115.625457 "$binary"`。来宾通过回环 AUR RPC 查询候选，依赖包按 Arch 签名校验安装，AUR 夹具的源码另有 GPG 签名。
- 普通计划仅列缺装包。完整升级计划同时列出缺装包 `1-1` 和已有包的升级候选 `2-1`。文本和 JSON 均显示候选及依赖。逐次去掉 helper、make 或可用构建用户，以来源定位错误，比较前后包数据库和受管 Git 配置。
