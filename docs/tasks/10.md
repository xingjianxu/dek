# #10 把授权公钥与 age 配置展开为目标端密钥资源

[GitHub Issue #10](https://github.com/xingjianxu/dek/issues/10) · Feature

- 分支：`issue-10-builtin-key-modules`
- Worktree：`/data/dek-dev/worktrees/10-builtin-key-modules/`

## 交付目标

使用户能以 JSON 或 Ruby 的标准 option 声明 SSH 受管授权条目和只在目标机解密的文件。

## 范围与接口

在 `crates/dek-controller` 的内置 `modules` 实现 SSH 授权与 age schema、展开器及路径语义文档。范围为声明、引用和密文元数据。目标机授权文件更新、私钥解密、漂移检测和原子落盘由 Linux 后端实现。

设计位置：[docs/design.md](../design.md) §2.3、§6.3。

直接前置：[#9](9.md)。

## 实施步骤

1. 映射 `users.users.<name>.openssh.authorizedKeys.{keys,keyFiles}`，把内联公钥与声明文件相对的公钥文件关联到对应账户。
2. 映射 `age.identityPaths`、`age.secrets.<name>.{file,path,owner,group,mode}`，区分仓库密文与目标机解密私钥、输出路径。
3. 为空授权集合、完全省略授权声明、加密文件依赖的父目录与账户分别保留可区分的资源语义。文档注明用户授权、客户端私钥与 SSH 服务端主机键的用途。

## 验收条件

- [ ] 用设计 §6.3 的目录布局从 `hosts/server/default.json` 引用 `../../keys/alice.pub` 与 `../../secrets/gitDeploy.age`，资源正确绑定 Alice、公钥来源和密文摘要，identity 与目标路径原样保留。
- [ ] 分别声明授权列表 `[]` 与省略整个资源，前者展开为显式管理的空集合，后者资源清单没有该授权资源。
- [ ] 在管理机不存在所声明 identity 文件的环境下展开设置，仍可得到绑定目标 identity 路径及 `0600` 权限的资源，管理端采集的内容仅含样本公钥、密文和元数据。
