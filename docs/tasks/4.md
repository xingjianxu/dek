# #4 用 dek init 和 hosts 初始化配置仓库并选择主机

[GitHub Issue #4](https://github.com/xingjianxu/dek/issues/4) · Feature

- 分支：`issue-4-manifest-hosts`
- Worktree：`/data/dek-dev/worktrees/4-manifest-hosts/`

## 交付目标

让用户能从仓库任意子目录找到清单、初始化 JSON 或 Ruby 入口，并一致地选中本机或远端主机。

## 范围与接口

在 `crates/dek-controller` 的 `repo` 实现 `dek.json` 解析、发现及主机选择，在 `crates/dek-cli` 接入 `init`、`hosts`、`--repo`、`-H/--host`、帮助与 `hosts --json`。选择 SSH 别名只生成目标描述，连接由传输层处理。

设计位置：[docs/design.md](../design.md) §2、§2.2、§7.1、§7.2、§9。

直接前置：[#1](1.md)。

## 实施步骤

1. 读取并验证 `schemaVersion`、主机入口及本机/SSH 绑定、profile 别名、模块 schema/expand/readsOptions 与 `inputs: "sdk"`。清单内路径按仓库根解析。
2. 从当前目录向上查找最近的清单，显式 `--repo` 优先。显式 host 必须存在，省略 host 时仅采用唯一匹配当前主机名的本地入口。
3. 实现 `dek init [目录] [--lang json|ruby]`、`dek hosts [--json]` 及帮助。生成以当前主机名命名的入口，写入前检查同名目标冲突。

## 验收条件

- [ ] 在空目录运行 `dek init` 和 `dek hosts --json`，输出列出当前主机、本地方式和可解析的 JSON 入口。另建目录用 `--lang ruby` 初始化得到 Ruby 入口。
- [ ] 对已初始化目录再运行 `dek init`，得到冲突文件名和非零退出码，已有配置内容不变。
- [ ] 准备嵌套的两份清单，从内层子目录运行 `dek hosts` 选择最近一份，使用 `--repo` 可显式选择外层。`-H server` 的解析结果保留 SSH 别名 `lab-server`。
- [ ] 在主机选择测试中使用未知名称、无本机匹配或非唯一匹配，得到明确诊断及可选主机。运行 `dek init --help`、`dek hosts --help` 均成功。
