# #34 为指定用户部署 systemd 服务和定时器并显示待激活状态

[GitHub Issue #34](https://github.com/xingjianxu/dek/issues/34) · Feature

- 分支：`issue-34-user-systemd`
- Worktree：`/data/dek-dev/worktrees/34-user-systemd/`

## 交付目标

让管理者在目标用户 manager 在线或离线时都能明确掌握该用户 unit 的部署、启用及运行结果。

## 范围与接口

在 dek-linux::systemd 增加指定账户作用域、用户 manager 探测、离线启用与动作结果，同时在计划和状态输出展现待激活状态。

设计位置：[docs/design.md](../design.md) §2.3、§6.1–6.2、§8③、§11、§12.4。

直接前置：[#32](32.md)、[#29](29.md)、[#28](28.md)。

## 实施步骤

1. 按作用域、账户与完整 unit 名建立资源身份。在目标机解析 UID、home 和用户 systemd 配置目录，校验已有账户或同计划的创建依赖。
2. 以指定用户权限写入 unit 文件与启用链接，针对各自在线的用户 manager 合并 daemon-reload 并执行启停。
3. 用户 manager 离线时完成可离线的部署与启用，将即时启动标为待激活；分别呈现文件、自启与运行状态。让 timer 驱动其 oneshot service。
4. 由管理员通过 `loginctl` 管理 linger。重新登录或管理员启用 linger 后，重新应用会完成仍需执行的激活。

## 验收条件

- [x] 管理员在 Arch 测试机给 Alice 部署 backup.service 与 backup.timer，同时预置 Bob 和系统级同名 unit，只有 Alice 的文件、链接及 manager 状态变化。
- [x] Alice 的 manager 在线时仅启用并启动 timer，待 oneshot 正常结束后 plan 为零动作。manager 离线时报告已部署、已启用、待激活，恢复在线并 apply 后可查询 timer 运行状态。
- [x] 指定不存在且未声明的用户时 plan 指明缺失账户，补充用户声明后先创建账户再成功部署。

使用离线 Arch 来宾运行 [`scripts/tests/user-systemd`](../../scripts/tests/user-systemd)。夹具以管理员身份切换 manager 在线状态，并读取三组同名单元的文件摘要、状态和 `ReloadCount`。
