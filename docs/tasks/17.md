# #17 按仓库和求值单元原子保存 MessagePack 缓存

[GitHub Issue #17](https://github.com/xingjianxu/dek/issues/17) · Feature

- 分支：`issue-17-cache-unit-store`
- Worktree：`/data/dek-dev/worktrees/17-cache-unit-store/`

## 交付目标

让 Rust 直接定位、校验和替换单个单元的缓存，并在写入竞争或文件损坏后恢复。

## 范围与接口

在 `dek-controller::cache` 实现 Linux 管理机路径适配、单元键、记录编解码与写入锁。使用 `dek-core` 已校验的领域数据，保留自定义映射的键名和来源信息。

设计位置：[docs/design.md](../design.md) §4.1、§4.2、§8、§9。

直接前置：[#2](2.md)。

## 实施步骤

1. 按本地工作副本隔离 repo-id，按阶段、规范化单元标识、参数及所用主机上下文计算单元键，定位 `$XDG_CACHE_HOME/dek/<repo-id>/units/<prefix>/<unit-key-hash>.mpk`。
2. 编码格式版本、求值器签名、依赖及其摘要、语义输出摘要、类型化结果与来源。固定结构按位置编码，输出摘要规范化对象键与无序集合，保留有序数组的顺序。
3. 将临时文件写入同一目录，提交时取得单元写锁并复核输入与磁盘记录。丢弃过期计算，只将完整且仍有效的计算结果原子替换到正式路径。
4. 命中时直接解码。记录损坏、版本不符和签名变化都作为本单元未命中处理。

## 缓存接口与验证

`CacheStore` 按工作副本和单元键读取类型化记录。调用者通过 `lookup` 取得记录及当时的文件版本，复用前自行核对依赖。重新求值后通过 `publish` 提交新记录和依赖复核函数。库对规范化 JSON 计算语义摘要，模块可用 `canonical_set` 表示无序集合。[缓存格式](../adr/17-unit-cache-format.md)

集成测试覆盖紧凑 MessagePack 记录、来源和嵌套映射往返，使用同步屏障重现晚到写入，并在子进程持锁复核时终止写进程。版本、签名、截断和多余字节分别触发当前单元的缓存未命中。[缓存测试](../../crates/dek-controller/tests/cache.rs)

## 验收条件

- [x] 对两个同内容的工作副本建立缓存，两者的 repo-id 路径不同。编辑同一单元后，替换的仍是原单元文件。
- [x] 用字段顺序不同的对象和成员顺序不同的无序集合计算摘要，值相等。互换有序数组元素后摘要改变。
- [x] 用同步屏障让旧计算晚于新计算提交，再在下一轮替换前终止写入。两次均能读到最近一次有效的完整记录。
- [x] 截断一个单元文件，再把另一个独立单元的记录留作对照。前者局部重建，后者直接命中。
