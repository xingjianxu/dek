# #8 把软件包、Git、OpenSSH 和 Caddy 选项展开为资源

[GitHub Issue #8](https://github.com/xingjianxu/dek/issues/8) · Feature

- 分支：`issue-8-builtin-app-modules`
- Worktree：`/data/dek-dev/worktrees/8-builtin-app-modules/`

## 交付目标

使静态 JSON 主机仅凭内置 schema 和 Rust 展开器即可声明常用软件及服务。

## 范围与接口

在 `crates/dek-controller` 的 `modules` 随程序发布应用 schema 与 Rust 展开器，并在模块文档记录对应公开路径、类型与 dek 行为。范围为声明映射。包事务、服务操作和目标文件写入由 `dek-linux` 实现。

设计位置：[docs/design.md](../design.md) §2.1–2.3、§3、§6、§7.3–7.4。

直接前置：[#7](7.md)。

## 实施步骤

1. 映射 `environment.systemPackages`、`dek.arch.aurPackages`，将官方仓库与 AUR 的包名分别保留来源。不引入配置版本锁。
2. 映射 `programs.git.enable/config`、`services.openssh.enable`、`services.caddy.enable/configFile`，保留第三方配置键拼写。
3. 为 Caddy 建立包、受管文件、需自启及运行的服务与配置变更通知之间的关系，记录各模块读取的 option 路径及来源。

## 实现与验证

`register_app_schemas` 注册内置应用选项，`register_app_modules` 注册对应的 Rust 展开器。模块记录精确读取的选项，组装阶段按生效定义的位置读取 Caddyfile。[内置应用选项](../modules/builtin-apps.md)

应用集成测试从配置仓库的静态 JSON 入口开始，覆盖 Git 配置拼写、官方仓库与 AUR 来源、OpenSSH 服务、Caddy 文件和重载通知，以及撤销管理后的资源清单。[集成测试](../../crates/dek-controller/tests/builtin_apps.rs)

## 验收条件

- [x] 在没有 Ruby 可执行文件的测试环境中展开 `programs.git.enable` 与 `programs.git.config = {"init":{"defaultBranch":"main"}}`，所得资源包含 Git 包与保留 `defaultBranch` 的配置。
- [x] 用 JSON 启用 Caddy 并引用 `Caddyfile`，资源含仓库包、带内容摘要的 `/etc/caddy/Caddyfile` 和 `caddy.service`。其自启、运行目标及变更通知可分别检查。
- [x] 同时声明官方包 `ripgrep` 和一个 AUR 包，两个资源保有不同来源。删去 Caddy 声明并重新展开，结果不请求卸包、删文件、停止或禁用服务。
