# #31 校验并原子替换 Linux 受管文件

[GitHub Issue #31](https://github.com/xingjianxu/dek/issues/31) · Feature

- 分支：`issue-31-linux-files`
- Worktree：`/data/dek-dev/worktrees/31-linux-files/`

## 交付目标

让文件按已审阅的内容和 POSIX 属性生效，单文件或成组校验失败时仍可使用旧文件。

## 范围与接口

在 dek-linux::filesystem 注册文件能力，实现目标端路径规范化、内容与元数据比对、暂存校验、替换和显式 absent。

设计位置：[docs/design.md](../design.md) §1.1、§2.2、§3、§4.3、§6、§7.3–7.4、§8③。

直接前置：[#14](14.md)、[#27](27.md)、[#23](23.md)。

## 实施步骤

1. 在目标机规范化文件标识并读取实际内容、属主与 mode，为声明内容、元数据漂移或显式删除生成独立可说明的动作。
2. 按计划摘要取得目标内容，在同一文件系统中暂存并设置目标属性；让需要联合校验的模块对全部暂存输入完成校验后再开始替换。
3. 校验成功后逐文件原子替换并复读，失败时清理暂存并保留诊断。给相关服务通知提供文件校验与实际替换结果。
4. 区分显式 absent 与撤销资源声明，已有内容和权限均达标时直接跳过写入。

## 验证命令

- `cargo test --locked -p dek-cli --test linux_files` 使用真实文件系统和目标端文件组校验器。无效成员导致整个组保留旧文件。修正后两份文件按审阅内容发布，验证也覆盖一份成员已经收敛的情况。
- 在 [#23 的 Arch 来宾](23.md)部署同一构建和本机 Ruby 运行时，运行 `scripts/tests/linux-files`。公开的 `plan` 和 `apply` 覆盖内容、属主、属组和权限，分别核对内容漂移与权限漂移。二次应用保留 inode 和 mtime，撤销声明保留文件，显式 absent 移除文件，已有符号链接拒绝规划。

实现和涉及的发布约定见 [ADR](../adr/31-linux-file-publication.md)。

## 验收条件

- [x] 部署 A 后手工改为 B 或修改 mode，plan 能区分内容与权限漂移；apply 修正后再次运行时 inode/mtime 和受管写入次数不变。
- [x] 用两个文件组成联合校验输入，第二个文件无效时两个旧文件内容均保留，临时文件被清理。修正后两份目标内容均为计划内的版本。
- [x] 撤销已部署文件的声明后 apply 仍可读该文件，显式 absent 后文件才消失，再次 apply 为零动作。
