# #32 分别管理系统级 systemd unit 的定义、自启与运行状态

[GitHub Issue #32](https://github.com/xingjianxu/dek/issues/32) · Feature

- 分支：`issue-32-linux-systemd`
- Worktree：`/data/dek-dev/worktrees/32-linux-systemd/`

## 交付目标

让系统级 unit 与 drop-in 按计划部署，并准确区分 daemon-reload、自启开关和服务启停。

## 范围与接口

在 dek-linux::systemd 注册系统级 unit 后端，接收内置模块产生的服务、定时器与 drop-in 资源。

设计位置：[docs/design.md](../design.md) §2.2–2.3、§3、§6、§7.4、§8③、§12.4。

直接前置：[#31](31.md)、[#9](9.md)。

## 实施步骤

1. 读取目标 systemd manager 的 unit 文件、启用状态与当前运行状态，分别生成定义部署、enabled、running 等动作。
2. 复用文件后端部署 unit 与 drop-in，同一批定义变化触发一次目标 manager 的 daemon-reload，随后依赖顺序执行启停。
3. 为显式 running: false、enabled: false 生成针对性动作，撤销整个声明后保留原 unit、启用状态和运行状态，执行后逐项核验。

## 验收条件

- [ ] 在 Arch 测试机同时更新两个 unit 定义及一个 drop-in，执行追踪仅有一次系统级 daemon-reload，重复 apply 时为零次。
- [ ] 对已运行且启用的服务仅声明 enabled: false，验证已禁用且服务仍运行；独立场景仅声明 running: false，验证服务已停且启用状态保持。
- [ ] 预置并管理一个已启用、运行中的服务，移除整个声明后 apply，systemctl is-enabled 与 is-active 的结果与执行前相同。
