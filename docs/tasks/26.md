# #26 按已确认的保留策略清理过期计划并保护恢复所需内容

## 交付目标

按可配置策略回收目标机上不再引用的计划与内容，同时保证有效计划和待恢复运行可用。

## 范围与接口

在 `dek-target::state` 管理有效期、执行及恢复引用和回收。维护者已确认默认有效期 7 天、目标端配置覆盖和保存新计划时回收。测试使用可控时钟和显式时长。

设计位置：[docs/design.md](../design.md) §4.3、§5、§7.2、§11。

直接前置：[#25](25.md)。

## 实施步骤

1. 在 Issue 记录默认过期时长、覆盖方式、清理触发时机的决定，按确认的策略实现配置和触发入口。
2. 索引有效计划及运行中/待恢复任务的引用，协调计划读取、引用固定与回收，避免进行中的事务丢失内容。
3. 过期计划拒绝新执行并提示重新规划，按审阅流程展示新 ID。仅在最后一个有效或恢复引用释放后回收相应对象。

## 使用

在目标状态根（默认 `/var/lib/dek`）放置 `retention.json`，其内容例如 `{"planTtlSeconds":86400}`。文件归可信目标端账户所有，权限为 `0600`。该文件缺省时采用 604800 秒。新的状态事务读取目标端配置。

`dek plan` 复用有效的相同计划。原审阅已过期时，重新规划返回不同的计划 ID。保存新计划时同步回收过期且没有进行中或待恢复引用的计划，以及没有剩余引用的内容对象。执行记录继续支持按 ID 查询，持久化的过期标记提供重新规划诊断。

## 验收条件

- [x] 用可控时钟使计划 A 过期，并让有效计划 B 引用同一内容。A 被拒绝新执行并要求审阅新 ID，B 的内容仍可读。
- [x] 在运行中和待重试两种状态分别推进时钟并执行回收。两次都能按 run_id 找到恢复所需的计划与对象，解除最后一个引用后才被清理。
- [x] 在读计划并固定引用的同时触发回收，结果只能是获得完整可用的计划或明确的过期错误，不出现部分内容已被清除的执行。

运行 `cargo test --locked -p dek-target retention_tests` 检查七天边界、目标配置、共同引用、恢复保留和读取固定与回收的互斥。运行 `cargo test --locked -p dek-cli --test planning cli_prints_the_newly_issued_plan_id_after_expiry` 检查终端和 JSON 显示的续发 ID 对应落盘计划。
