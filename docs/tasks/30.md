# #30 按目标路径管理目录的属主、属组与权限

[GitHub Issue #30](https://github.com/xingjianxu/dek/issues/30) · Feature

- 分支：`issue-30-linux-directories`
- Worktree：`/data/dek-dev/worktrees/30-linux-directories/`

## 交付目标

按目标机解析的账户和路径创建或修正目录，并在撤销声明后保留已有数据。

## 范围与接口

在 dek-linux::filesystem 注册 Directory 后端，处理 directory 与 systemd.tmpfiles.settings 的标准化资源、类型检查与目录元数据。

设计位置：[docs/design.md](../design.md) §2.3、§6.2、§8③、§9。

直接前置：[#29](29.md)。

## 实施步骤

1. 解析目标绝对路径、用户/组和字符串 mode，读取目录自身元数据。遇普通文件或符号链接时让 plan 报路径类型冲突。
2. 将创建或修正动作依赖到同批账户/组，实际执行时解析刚分配的 ID，再复读属主、属组及权限。
3. 将修改限定到受管目录本身。采用 systemd-tmpfiles 时只提交本次 d 规则，处理路径转义；若使用持久规则，撤销声明时停用 dek 写入的对应规则。

## 验收条件

- [x] 在 Arch 测试机声明 research、alice、/srv/research 和 0750，apply 后 stat 返回 alice、research、750，再次 plan 为零动作。
- [x] 预置目录内权限为 0640 的文件，修改目录为 0777，再 apply 仅修正目录权限，子文件内容和 mode 不变。已有普通文件或符号链接占用目标路径时 plan 报错。
- [x] 模拟账户创建后目录操作失败，解除故障再 apply，沿用原 UID/GID 补完目录。移除声明并重启测试机，目录、子文件和手工设置的权限均保留。

## 验证命令

- 开发机运行 `./scripts/check`。CLI 夹具覆盖父目录依赖、属性修正、子文件、文件和符号链接冲突、已审阅目标的 inode 替换，以及撤销声明。
- 使用 `scripts/run-arch-vm` 启动专用 Arch 客机，通过 `ssh` 以 root 执行 `scripts/tests/linux-directories exercise`，然后调用 `reboot` 并在同一客机执行 `scripts/tests/linux-directories after-reboot`。脚本检查实际分配的 UID/GID、同一 run 的失败补完及重启后的状态。
