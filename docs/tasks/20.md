# #20 通过 refresh 更新显式声明的 HTTP 输入并支持离线复用

[GitHub Issue #20](https://github.com/xingjianxu/dek/issues/20) · Feature

- 分支：`issue-20-cache-refresh-inputs`
- Worktree：`/data/dek-dev/worktrees/20-cache-refresh-inputs/`

## 交付目标

让管理机在 `dek refresh -H <host>` 中更新该主机显式引用的外部输入，普通求值使用已缓存的响应。

## 范围与接口

在 `dek-controller` 管理 HTTP 输入的标识、响应与摘要，在 `dek-cli` 装配 `refresh`。沿用 SDK 已记录的显式请求和现有的仓库、主机解析逻辑。

设计位置：[docs/design.md](../design.md) §4.2、§5、§7.2。

直接前置：[#18](18.md)、[#4](4.md)、[#16](16.md)、[#19](19.md)。

## 实施步骤

1. 支持从冷缓存配置识别显式 HTTP 输入，并在日常求值缺少响应时指出具体输入及刷新方式。
2. 让 `refresh` 只对选中主机引用的输入发起请求。成功响应经校验后完整替换缓存，并让输入摘要进入依赖清单。
3. 通过 [#16](16.md) 的普通规划入口与 [#19](19.md) 的增量节点使用本地响应。刷新失败报告对应输入并维持已有成功响应，内容未变化时保留下游命中。

## 验收条件

- [x] 用本地 HTTP 测试服务计数，首次普通规划提示缺失输入且请求数为零。执行 `refresh -H server` 后关闭服务，再次普通规划仍成功。
- [x] 两个 host 各引用不同 URL，更新 server 的响应并刷新 server 后，只有该 URL 被请求、读取它的单元失效。相同内容再次刷新不会使该单元失效。
- [x] 将曾成功提供内容的服务改为返回错误。刷新报错并指出输入，后续离线规划仍可读取上次的成功内容。

wks-lab 的本地 HTTP 服务用例覆盖冷缓存零请求、只刷新选定主机当前输入、启用模块的 URL 切换、相同正文复用和失败后离线规划。部分响应和无效 UTF-8 保留上一份数据。
