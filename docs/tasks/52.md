# #52 记录真实配置的增量规划成本与缓存编码基准

[GitHub Issue #52](https://github.com/xingjianxu/dek/issues/52) · Task

- 分支：`issue-52-benchmark-evaluation`
- Worktree：`/data/dek-dev/worktrees/52-benchmark-evaluation/`

## 交付目标

用可复现数据比较冷/热及局部变更的总成本，并衡量两种编码在真实配置上的实际开销。

## 范围与接口

在基准测试入口与 `dek-controller`、传输测试适配层记录计数，以已具代表性的真实配置运行 `serde_json` 与 `rmp-serde` 对照。报告保存到当次 run 目录。生产缓存继续采用设计指定的 MessagePack。

设计位置：[docs/design.md](../design.md) §4.1、§4.2、§8、§10.6–§10.8。

直接前置：[#21](21.md)、[#42](42.md)、[#23](23.md)。

## 实施步骤

1. 选取可复现的实际配置和固定目标初态，记录测试环境、提交 SHA、输入规模、镜像、缓存清理方式及计时边界。准备冷、热、单文件编辑、公共 profile 编辑四种情形。
2. 收集每种情形的端到端耗时、Ruby 启动次数、失效单元数、SSH 往返和文件内容传输字节，可用本机路径作为对照，并给出重复运行结果。
3. 对相同的已验证记录分别以紧凑 JSON 与 MessagePack 编码、热命中解码和整轮规划。包含版本头、依赖、来源，记录编码字节及实际磁盘占用。
4. 输出可复跑的命令、结果原始文件及基于实测的耗时指标建议，具体阈值留待原型实机数据评审。

## 验收条件

- [ ] 从同一初态重跑报告中的命令，四种场景均列出总耗时、脚本启动次数、失效单元数、SSH 往返次数和传输字节，数值可追溯到本轮原始记录。
- [ ] 在已同步且输入未变的热路径上，标记 SDK 的 Ruby 启动数和内容传输字节均为 0。改变一个静态文件后，报告可识别新增传输量而 Ruby 仍命中。
- [ ] 以同一批带依赖和来源的记录对照两种编码，解码得到等价结果，报告分别列出编码耗时、热解码耗时、端到端耗时、载荷大小和磁盘占用。
