# #38 通过 Arch 本地包数据库识别已满足与显式移除的声明

[GitHub Issue #38](https://github.com/xingjianxu/dek/issues/38) · Feature

- 分支：`issue-38-arch-package-state`
- Worktree：`/data/dek-dev/worktrees/38-arch-package-state/`

## 交付目标

让已有依赖包的主机离线完成普通规划和应用，并准确区分包已安装、缺失和显式要求移除。

## 范围与接口

在 dek-linux::arch 注册 pacman 仓库包后端，按包来源和名称读取本地数据库，接入明确的包移除及核验。

设计位置：[docs/design.md](../design.md) §1、§2.2–2.3、§6、§7.4、§8③、§9。

直接前置：[#8](8.md)、[#27](27.md)、[#23](23.md)。

## 实施步骤

1. 区分官方仓库包与受管 AUR 包来源，用目标机的已安装包信息生成包状态及缺包输入，版本作为事务和诊断信息使用。
2. 当普通 plan/apply 的声明包均已满足时，直接走本地快路径，完全跳过软件源刷新与升级检查。
3. 为明确的 absent 预览将受影响的事务，按预览执行并从本地数据库复核；移除声明仅停止管理。

## 使用和验证

Arch 目标注册官方 pacman 包后端。已安装包通过本地查询满足 `environment.systemPackages`。自定义模块以 `resource('package', package: {source: 'official', name: 'tree'}, state: 'absent')` 明确声明移除。关闭管理时移除配置声明即可。目标端实际移除需要 root 权限。

读取已安装状态使用 `pacman --query`。移除预览使用 `pacman --remove --print --print-format`，审阅记录保存包标识和已安装版本。实际移除使用原生 pacman 事务，并在事务锁内通过临时前置 hook 复核唯一目标和版本。缺失包会定位到包名并提示候选版本需求。仓库数据与 AUR 处理由后续任务接入。 [pacman 手册](https://man.archlinux.org/man/pacman.8.en) · [移除事务 ADR](../adr/38-arch-local-package-removal.md)

`scripts/tests/arch-package-state <镜像标识> <dek 构建> <ripgrep 归档> <tree 归档> <旧版 tree 归档>` 通过 #23 的来宾执行验收。每个输入归档旁须有对应的 `.sig`，来宾使用 Arch keyring 严格验签且以本地文件播种。两版 tree 用于在最后一次预览与真正卸载之间触发版本漂移。脚本使用开发机已有的 Ruby Nix 闭包，来宾的外网转发保持关闭。

## 验收条件

- [x] 在已安装 ripgrep 的 Arch 测试机阻断外网，令探针记录包后端调用。普通 plan/apply 均报告该包已满足，刷新和升级检查计数为 0。
- [x] 撤销 ripgrep 声明后 apply，pacman -Q ripgrep 仍成功；另一个没有反向依赖的测试包明确设为 absent 时，计划列出移除，按计划执行后查询返回未安装。
- [x] 声明一个未安装仓库包时计划侧识别缺包。同名不同来源的资源具有不同标识，配置中仅需名称与来源。

已使用 `v20261115.625457`、`ripgrep 15.2.0-1` 及 `tree 2.3.2-1 / 2.3.1-1` 验证。普通满足路径的探针只记录本地查询。签名旧版 tree 在最后一次预览后安装，原审阅被事务守卫拒绝。重新审阅成功卸载，ripgrep 与同步数据库保持原样。 [ripgrep 发布信息](https://archlinux.org/packages/extra/x86_64/ripgrep/) · [tree 发布信息](https://archlinux.org/packages/extra/x86_64/tree/)
