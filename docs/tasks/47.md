# #47 经确认执行完整 pacman 升级并复核后续配置

[GitHub Issue #47](https://github.com/xingjianxu/dek/issues/47) · Feature

- 分支：`issue-47-arch-upgrade-apply`
- Worktree：`/data/dek-dev/worktrees/47-arch-upgrade-apply/`

## 交付目标

让 dek upgrade 和 apply --plan 只执行用户审阅的完整包事务，升级后将计划外配置变化交还审阅。

## 范围与接口

在 dek-cli 实现 upgrade 的交互确认与非交互输出，在 dek-linux::arch 和 dek-target::executor 复核并执行完整仓库事务。

设计位置：[docs/design.md](../design.md) §4.3、§5、§6、§7.2–7.4、§8⑤。

直接前置：[#45](45.md)、[#28](28.md)。

## 实施步骤

1. 交互终端展示完整清单并等待确认，非交互模式返回待审阅计划，普通 apply 触发升级时提示带主机参数的 apply --plan 命令。
2. 在目标锁内重算包事务与候选版本，按原计划的仓库和主机绑定校验。范围或版本有变时保存并展示新计划。
3. 确认后按一次完整 pacman 事务完成仓库升级与缺包补装，从本地包数据库核验并记录结果，再调用适用的受管 AUR 阶段。
4. 包升级完成后复核配置，按计划执行预见到的动作。产生计划外新动作时返回新计划，保留已完成事务。

## 验收条件

- [ ] 在伪终端取消确认以及无终端运行 upgrade，均可得到审阅信息，已安装版本与配置保持不变。用确认后的计划 ID 执行时输出 run_id。
- [ ] 记录升级调用，确认一次 pacman 事务同时完成已安装包升级与缺包补装。更换测试源的候选版本或新增被替换的包后执行旧计划，返回新 ID 且没有包被升级。
- [ ] 构造包升级后突然出现的配置动作，命令返回新计划，并可通过 status 查到已完成的包事务；新动作在得到确认前未执行。
