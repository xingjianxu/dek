# #44 在两台无 Ruby 的 Arch 目标机验收远程计划、应用与故障恢复

[GitHub Issue #44](https://github.com/xingjianxu/dek/issues/44) · Task

- 分支：`issue-44-accept-ssh`
- Worktree：`/data/dek-dev/worktrees/44-accept-ssh/`

## 交付目标

通过真实 OpenSSH 与独立 Arch 来宾，验证阶段④在错误目标、旧计划、丢失回执和跨主机使用时的行为。

## 范围与接口

在 `crates/dek-cli/tests/` 与专用 VM 集成入口使用两台新实例，管理机保存配置仓库与 Ruby，目标端仅部署本次 dek 及用例所需系统服务。

设计位置：[docs/design.md](../design.md) §4.3、§5、§7.2、§8、§10.6、§10.8。

直接前置：[#43](43.md)、[#41](41.md)、[#26](26.md)、[#23](23.md)、[#31](31.md)、[#32](32.md)、[#33](33.md)。

## 实施步骤

1. 给两台来宾分配独立主机标识、SSH 别名及状态目录，核对两机均无 Ruby 和配置仓库。设置能通过实际 systemd 记录调用次数的测试服务。
2. 从同一管理仓库分别运行远程规划、按 ID 执行及查询，核对计划与事实归属、文件内容和二次应用结果。
3. 在来宾中注入可重复的过期与连接中断，重放同一已受理请求并查询原 run。记录两个来宾的文件摘要、服务调用次数、受管状态和命令输出。

## 验收条件

- [x] 在 A 上 `plan --json`、`apply --plan` 后文件字节正确，二次 plan 零动作。B 的同路径文件和服务计数保持原值。A 的目标事实与 B 的同名项可区分。
- [x] 把 A 的 SSH 别名连到 B，以及在 B 上使用 A 的计划 ID，均被拒绝且两边无意外变更。使用测试时钟/配置使计划过期，旧计划被拒绝并展示新 ID，等待审阅。
- [x] 在目标完成一次服务通知、管理端收到回执前断开真实 SSH。重连并以 `dek status -H a --run <ID> --json` 查回同一次执行，再次发送同一请求后，a 的服务调用记录仍只有一次。

## 验证命令

- 按 [#23](23.md) 准备 Arch ABI 的目标机二进制。运行 `scripts/tests/ssh-convergence v20261115.625457 "$manager" "$guest"`，或给 `cargo test --locked -p dek-cli --test ssh_convergence -- --ignored` 提供 `DEK_TEST_ARCH_IMAGE` 和 `DEK_TEST_ARCH_BINARY`。
- 两个新 Arch 来宾都无 Ruby 和配置库。管理机端复用同一个配置与 Ruby，两个目标事实的摘要和审阅内容各自绑定。VM 的测试 SSH 账户使用已有的 sudo 配置调用真实目标端，以验证系统服务。
- 测试在真实 OpenSSH 收到完整执行结果后丢弃回执。原运行的文件和服务动作各记录一次尝试，重复请求沿用原 ID，实际 systemd 重载计数仍为一。另用 1 秒保留策略令旧计划过期，确认新 ID 已保存，A 与 B 的目标观测均符合预期。
- 证据位于 `/data/dek-dev/runs/44/ssh-convergence.*/`，包含两台来宾的身份、目标配置摘要、服务计数及管理机的计划和状态输出。
