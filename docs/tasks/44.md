# #44 在两台无 Ruby 的 Arch 目标机验收远程计划、应用与故障恢复

[GitHub Issue #44](https://github.com/xingjianxu/dek/issues/44) · Task

- 分支：`issue-44-accept-ssh`
- Worktree：`/data/dek-dev/worktrees/44-accept-ssh/`

## 交付目标

通过真实 OpenSSH 与独立 Arch 来宾，验证阶段④在错误目标、旧计划、丢失回执和跨主机使用时的行为。

## 范围与接口

在 `crates/dek-cli/tests/` 与专用 VM 集成入口使用两台新实例，管理机保存配置仓库与 Ruby，目标端仅部署本次 dek 及用例所需系统服务。

设计位置：[docs/design.md](../design.md) §4.3、§5、§7.2、§8、§10.6、§10.8。

直接前置：[#43](43.md)、[#41](41.md)、[#26](26.md)、[#23](23.md)、[#31](31.md)、[#32](32.md)、[#33](33.md)。

## 实施步骤

1. 给两台来宾分配独立主机标识、SSH 别名及状态目录，核对两机均无 Ruby 和配置仓库。设置能通过实际 systemd 记录调用次数的测试服务。
2. 从同一管理仓库分别运行远程规划、按 ID 执行及查询，核对计划与事实归属、文件内容和二次应用结果。
3. 在来宾中注入可重复的过期与连接中断，重放同一已受理请求并查询原 run。记录两个来宾的文件摘要、服务调用次数、受管状态和命令输出。

## 验收条件

- [ ] 在 A 上 `plan --json`、`apply --plan` 后文件字节正确，二次 plan 零动作。B 的同路径文件和服务计数保持原值。A 的目标事实与 B 的同名项可区分。
- [ ] 把 A 的 SSH 别名连到 B，以及在 B 上使用 A 的计划 ID，均被拒绝且两边无意外变更。使用测试时钟/配置使计划过期，旧计划被拒绝并展示新 ID，等待审阅。
- [ ] 在目标完成一次服务通知、管理端收到回执前断开真实 SSH。重连并以 `dek status -H a --run <ID> --json` 查回同一次执行，再次发送同一请求后，a 的服务调用记录仍只有一次。

提交与 PR 验证按[协作约定](../../AGENTS.md)执行。
