# #37 仅在目标机解密并原子部署 age 私钥文件

[GitHub Issue #37](https://github.com/xingjianxu/dek/issues/37) · Feature

- 分支：`issue-37-age-secret-apply`
- Worktree：`/data/dek-dev/worktrees/37-age-secret-apply/`

## 交付目标

让预置 identity 的目标机安全落盘审阅过的密文，并仅在明文实际变化时触发下游动作。

## 范围与接口

在 dek-linux::secrets 实现目标端解密、受保护的验证标记更新、路径及元数据复核和依赖通知。使用测试专用 identity 与私钥夹具。

设计位置：[docs/design.md](../design.md) §1、§4.3、§6.3、§8③、§9。

直接前置：[#36](36.md)、[#30](30.md)、[#33](33.md)。

## 实施步骤

1. 执行前复核父目录、最终路径、所有者和权限，防止写入路径上的可替换符号链接，拒绝覆盖用于解密的 identity。
2. 从目标端受保护位置读取预置 identity，完整解密并校验后在目标文件系统上以受限权限暂存，设置最终属主与 mode 后原子替换。
3. 比较目标与解密后的实际字节，区分仅更换收件人、元数据漂移和内容变化。复读并更新验证标记，按真实内容变化触发依赖。
4. 失败时清理临时文件，保留既有文件与依赖服务。保证输出、错误、缓存与运行记录仅包含允许的诊断字段。

## 验收条件

- [x] 在 Arch 测试机首次部署测试密文，stat 返回所声明的属主、属组和 0600。再次 apply 为零写入。手工修改明文后 plan 检出，apply 恢复；单改权限只修正元数据。
- [x] 对相同明文更换收件人重新加密后 apply，服务通知计数与目标文件内容均保持原值；改换真正的私钥后服务收到相应通知。
- [x] 分别提供损坏密文和不匹配 identity，均报告失败，旧文件字节、依赖服务状态保持，临时文件已清理。在可替换符号链接和 identity 自身路径上验证写入被拒绝。
- [x] 以可搜索的测试私钥标识核验缓存、已保存计划、执行记录、diff 与错误输出，均找不到明文标识。

## 验证命令

开发机运行 `./scripts/check`。Arch 验收先用 `scripts/tests/age-secret-apply prepare <目录>` 和主机的 `age` 生成临时密文及测试 identity。将这些夹具打包送入一次性 Arch 来宾，然后以 root 运行 `scripts/tests/age-secret-apply guest <归档>`。来宾使用 dek 的目标端解密，无须安装 age 命令。

实现记录见 [ADR #37](../adr/37-age-secret-deployment.md)。
